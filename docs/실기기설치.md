# 실기기 설치

안드로이드 폰에 깔아서 직접 해 보는 방법. 이 게임에서 **사람만 확인할 수 있는 것들**(손맛·프레임률·뒤로가기·
몰입 모드·실제 터치 크기)이 있어서, 여기까지 와야 비로소 알 수 있는 게 있다.

남에게 줄 주소는 공식 사이트다 — <https://kimd10041004-gif.github.io/-catpaw-defense/> (다운로드 버튼 한 개).
아래는 그 뒤에서 무슨 일이 일어나는지와, 개발자에게 필요한 다른 길들이다.

---

## 1. 폰에서 바로 받기 (권장)

**Releases → `dev` → APK 탭.**

```
https://github.com/kimd10041004-gif/-catpaw-defense/releases
```

`dev` 는 개발 빌드다. 최신으로 갱신하려면 **Actions → `릴리스 (설치용 APK)` → Run workflow** 를 한 번 누른다
(약 3분). 태그가 `dev` 로 고정이라 **받는 주소가 늘 같다** — 폰 북마크에 두고 써도 된다.

정식 버전을 내려면 태그를 민다:

```bash
node tools/bump-version.mjs patch     # 다섯 곳(package.json · version.js · sw.js · build.gradle.kts · site/index.html) 을 함께 올린다
git commit -am "v1.0.1" && git tag v1.0.1 && git push && git push --tags
```

### 어느 APK 를 깔까 — 둘 다

| 파일 | 패키지 | 왜 |
|---|---|---|
| `catpaw-defense-1.0.0-release.apk` | `com.catpaw.defense` | **이걸 먼저.** R8·리소스 축소가 켜진 진짜 빌드다. R8 이 `BillingBridge` 같은 걸 잘못 지웠는지는 **기기에서 돌려야만** 드러난다 — `proguard-rules.pro` 가 지키게 돼 있지만 그건 코드로 쓴 것이지 확인한 게 아니다 |
| `catpaw-defense-1.0.0-debug.apk` | `com.catpaw.defense.debug` | 디버그. 패키지가 달라 릴리스와 **나란히** 깔리고 세이브(localStorage)도 따로다. 릴리스에서만 나는 문제를 가릴 때 옆에 두고 비교한다 |

### 설치 허용

안드로이드 8 이상은 **앱별로** 허용한다. APK 를 탭하면 안내가 뜨는데, 수동으로 가려면:

```
설정 → 앱 → 특별한 앱 액세스 → 출처를 알 수 없는 앱 설치 → (크롬 / 내 파일) → 허용
```

### 서명 주의

지금 릴리스 APK 는 **디버그 키로 서명돼 있다**(키스토어 비밀 4개가 저장소에 없어서 — `출시체크리스트` §1).
나중에 Play 판(진짜 키)을 깔려면 **이걸 먼저 지워야 한다** — 서명이 다르면 덮어쓰기가 안 된다.
지울 때 그 앱의 세이브도 같이 지워진다.

## 2. PC 에서 (ADB)

```bash
adb install -r catpaw-defense-1.0.0-release.apk
```

`-r` 는 덮어쓰기다(같은 서명일 때만 된다). 세이브가 남는다.

**폰 안의 콘솔을 보려면** — 이게 실기기에서 제일 쓸모 있다:

1. 폰: 설정 → 휴대전화 정보 → 빌드번호 7번 탭 → 개발자 옵션 → **USB 디버깅** 켜기
2. PC 크롬 주소창에 `chrome://inspect` → 폰의 WebView 옆 **inspect**
3. 게임 화면의 콘솔·네트워크·프로파일러가 그대로 열린다. `출시체크리스트` §5 의 "콘솔 에러 0" 은 여기서 본다

## 3. 지금 당장 (Release 를 안 만들고)

**Actions → 최신 실행 → Artifacts → `catpaw-defense-release-apk`** (또는 `-debug-apk`).

아무 푸시에나 만들어진다. 다만 아티팩트는 **ZIP 으로 감싸여 있고**(폰에서 압축을 풀어야 한다) **로그인해야
받아지고** 30일 뒤 사라진다. 폰에서 할 거면 1번이 낫다.

---

## 4. APK 없이 (PWA)

`web/` 을 아무 데나 HTTP 로 올리고 안드로이드 크롬에서 열면 **⋮ → 홈 화면에 추가**. 전체화면·세로 고정으로
뜨고 서비스 워커가 전부 캐시해서 비행기 모드에서도 돈다. 같은 와이파이면 PC 에서 서버만 띄워도 된다:

```bash
npm run serve            # → http://<PC 의 IP>:8080
```

GitHub Pages 는 **공식 사이트(`site/`)가 이미 쓰고 있지만 게임은 안 올린다** — 웹의 데모 결제가 살아 있어서
유료 콘텐츠까지 열리기 때문이다(5번 끝을 보라). 그리고 저장소를 Private 으로 바꾸면 Pages 자체에 유료 플랜이
필요해진다.

PWA 와 APK 는 세이브가 서로 다른 곳(브라우저 vs WebView)에 있어 **진행도가 안 넘어간다**.

---

## 5. 아이폰은?

**아이폰용 앱은 없다.** `ios/` 도 Xcode 프로젝트도 스위프트 한 줄도 없다. 만들려면 **맥**(Xcode 가 맥에서만 돈다)과
**애플 개발자 계정**(연 $99, 없으면 7일마다 다시 서명해야 한다)이 필요하고, 둘 다 여기 없다. 안드로이드는
리눅스 CI 에서 공짜로 컴파일되는데 아이폰은 그게 안 된다 — 그래서 안드로이드만 있다. 숨길 일이 아니라 그냥 사실이다.

APK 는 아이폰에 **못 깐다**. 확장자를 바꿔도, 사이드로드 도구를 써도 안 된다 — 안드로이드 실행 파일 형식이라서다.

### 웹앱(PWA)으로는 열 수 있게 준비돼 있다

게임 자체는 웹 기술로 만들어서, `web/` 을 아무 데나 HTTPS 로 올리면 사파리에서 **공유 → 홈 화면에 추가**로
앱처럼 깔린다. 아이폰용 배선은 이미 코드에 들어 있다:

| 코드 | 하는 일 |
|---|---|
| `apple-mobile-web-app-capable` (`web/index.html:9`) | 주소창 없는 앱 화면으로 뜬다 |
| `apple-touch-icon` (`:15`) | 홈 화면 아이콘 |
| `viewport-fit=cover` + `env(safe-area-inset-*)` 9곳 | 노치와 홈 인디케이터를 피해 그린다 |
| 서비스 워커 (`web/sw.js`) | 비행기 모드에서도 돈다 |
| 첫 터치의 `audio.unlock()` (`main.js:109` 외) | iOS 는 사용자 조작 전엔 소리를 안 낸다 |

**안드로이드와 다른 점 넷** (고쳐서 되는 게 아니라 iOS 사파리의 한계다):

1. **상태바가 겹친다.** iOS 는 `display: fullscreen` 을 모른다 — `standalone` 까지만 된다.
   시계·배터리가 반투명으로 위에 얹힌다(안전 영역으로 피해 그리니 가려지지는 않는다).
2. **회전 잠금이 안 걸린다.** 매니페스트의 `"orientation": "portrait"` 를 iOS 가 무시한다.
   가로로 돌리면 지도 타일이 8.6px 로 줄어 **실질적으로 못 논다**(측정값). 폰의 회전 잠금을 켜고 하는 수밖에 없다.
3. **설치를 손으로 해야 한다.** 안드로이드 크롬처럼 "설치하시겠습니까" 가 안 뜬다.
   공유 버튼 → 홈 화면에 추가를 사람이 찾아야 한다.
4. **진동이 없다.** `navigator.vibrate` 를 사파리가 지원하지 않는다. `main.js:536` 이 미리 막아 둬서 오류는 안 나고,
   그냥 안 떨릴 뿐이다.

### 그런데 지금은 웹 빌드를 안 올려 뒀다

공식 사이트(`site/`)는 **다운로드 안내만** 올린다. 게임(`web/`)을 같이 올리면 웹의 '데모 결제'가 살아 있어서
**3막과 스킨 팩까지 결제 없이 열린다** — 파는 물건을 그냥 나눠 주는 셈이다(README 과금 절).

열려면 **무료 범위(자유 모드 6맵 · 시나리오 1~2막 · 도전 5종 · 펫 · 훈련 · 무한 · 주간)만 켠 데모 빌드**를
따로 구워야 한다. 빌드 분기 하나와 "데모에 유료 콘텐츠가 안 들었다" 는 검사가 필요하다. 아직 안 했다.

특히 **헤드리스로는 못 보는 것**만 추리면:

- 손맛 — 고양이를 끌어다 놓는 느낌, 탭이 씹히지 않는지
- 프레임률 — 저사양 기기의 30웨이브. `chrome://inspect` 의 프로파일러로 잰다
- 실제 손가락 크기 — 헤드리스는 마우스라서 작은 버튼도 다 눌린다
- 몰입 모드·뒤로가기 — 에뮬레이터가 없어 한 번도 확인된 적이 없다
- 가로 회전 — 깨지지는 않지만 지도 타일이 8.6px 로 줄어 실질적으로 못 논다(측정값). 세로로 쓰는 게 맞다

이상한 걸 찾으면 화면 녹화나 `chrome://inspect` 의 콘솔 로그를 그대로 가져오면 된다.
