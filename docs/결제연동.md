# 실제 결제 연결하기

지금 상태는 **결제가 연결되지 않은 상태**다. 이건 미완성이 아니라 의도한 기본값이다.

| 환경 | 지금 동작 |
|---|---|
| 웹 / PWA | `MockBillingProvider` — 버튼을 누르면 캣닢이 지급되고 상점에 **"데모 결제 (실제 청구 없음)"** 이라고 표시된다 |
| 안드로이드 APK | `BillingBridge`가 `configured = false`라 `not_configured`를 돌려준다. 상점에 **"Google Play 결제 (미설정)"** 으로 표시되고 결제는 실패한다 |

**어느 쪽도 실제로 청구되지 않고, 청구된 척하지도 않는다.** 진짜 결제를 켜려면 아래를 따른다.

---

## 왜 여기서 끝내뒀는가

실제 결제를 켜려면 코드만으로는 안 되고 다음이 전부 필요하다. 전부 사람이 계정으로 해야 하는 일이다.

1. Google Play Console 개발자 계정 (등록비 $25, 1회)
2. 앱을 Play Console에 등록하고 **서명된 릴리스 AAB**를 최소 한 번 업로드 (내부 테스트 트랙이면 충분)
3. 판매자 계정(Google Payments) 등록 — 국가·세금·정산 계좌
4. 상품 ID 등록
5. 라이선스 테스터 계정 등록

이걸 하지 않은 채 결제 코드를 넣으면 **버튼은 있는데 항상 실패하는 상태**가 된다.
그래서 "실패를 정직하게 드러내는 브리지"까지만 만들어두고, 나머지는 아래 절차로 남긴다.

---

## 1. Play Console에 상품 등록

`web/js/domain/shop.js`의 `sku` 값과 **정확히 같은 ID**로 만든다.

| 상품 ID (sku) | 유형 | 참고 |
|---|---|---|
| `catnip_100` | 소모성 (Consumable) | 캣닢 100개 |
| `catnip_600` | 소모성 (Consumable) | 캣닢 600개 |
| `premium_pack` | 비소모성 (Non-consumable) | 프리미엄 팩 (영구) |

가격은 Play Console에서 정한다. `shop.js`의 `priceLabel`은 화면 표시용 문자열일 뿐이므로
Play Console 가격과 다르면 직접 맞춰야 한다. (정확히 맞추려면 3번의 `queryProductDetails`에서
받아온 실제 가격 문자열을 `describe()`로 웹에 내려주면 된다.)

## 2. Gradle 의존성 추가

`android/app/build.gradle.kts`:

```kotlin
dependencies {
    implementation("com.android.billingclient:billing-ktx:7.1.1")
}
```

## 3. BillingBridge 구현

`android/app/src/main/java/com/catpaw/defense/BillingBridge.kt`에서:

1. `private val configured = false` → `true`
2. 생성자로 `Activity`를 받는다 (`launchBillingFlow`에 필요하다)
3. `purchase(sku)`의 주석 자리에 실제 흐름을 넣는다:

```
BillingClient.newBuilder(context)
  .setListener(purchasesUpdatedListener)
  .enablePendingPurchases()
  .build()
  → startConnection()
  → queryProductDetailsAsync(sku)
  → launchBillingFlow(activity, params)
  → onPurchasesUpdated 콜백에서 purchase.purchaseToken 확보
  → 소모품이면 consumeAsync, 영구 상품이면 acknowledgePurchase
```

4. 결과를 이 JSON 형태로 돌려준다 (웹 쪽 계약):

```json
{"ok": true,  "token": "<purchaseToken>"}
{"ok": false, "code": "user_canceled", "message": "사용자가 취소했습니다"}
```

5. `restore()`는 `queryPurchasesAsync` 결과를 이 형태로:

```json
[{"sku": "premium_pack", "token": "<purchaseToken>"}]
```

**중요:** `purchase()`는 자바스크립트 스레드에서 호출되는데 결제는 비동기다.
`CompletableDeferred`로 결과를 기다리거나, 콜백 방식으로 바꾸려면
`webView.evaluateJavascript("window.__catpawBillingResult(...)")` 로 되돌려주고
`billing.js`의 `AndroidBillingProvider.purchase`를 Promise 기반으로 고치면 된다.

## 4. 영수증 검증 (돈이 걸린 부분)

`applyPurchase()`는 클라이언트에서 중복 지급만 막는다. **위조는 막지 못한다.**
캣닢이 실제 매출과 연결된다면 서버에서 검증해야 한다:

```
Google Play Developer API
  purchases.products.get(packageName, productId, token)
  → purchaseState == 0 (구매됨) 확인
  → 이미 처리한 token인지 서버 DB로 확인
```

이 게임은 진행도가 기기 로컬(localStorage)에만 있으므로 서버가 없다.
그래서 지금 구조는 **"기기 안에서 잘 동작하는" 수준**이고, 매출 규모가 생기면
계정 시스템과 서버 검증을 먼저 붙여야 한다. 이 한계를 알고 쓰는 것이 중요하다.

## 5. 테스트

1. Play Console → 설정 → 라이선스 테스트 → 테스터 Gmail 등록
2. 내부 테스트 트랙에 AAB 업로드 후 그 계정으로 설치
3. 결제창에 "테스트 카드, 항상 승인됨"이 뜨면 정상

## 확인용 체크리스트

- [ ] `shop.js`의 `sku` 3개가 Play Console 상품 ID와 글자까지 같다
- [ ] `BillingBridge.configured = true`
- [ ] 상점 화면 상단이 "Google Play 결제 (미설정)"이 아니라 "Google Play 결제"로 뜬다
- [ ] 소모품(`catnip_*`)은 `consumeAsync`를 불러 재구매가 가능하다
- [ ] 영구 상품(`premium_pack`)은 `acknowledgePurchase`를 부른다 (3일 내 안 하면 자동 환불된다)
- [ ] `restore()`가 재설치 후 프리미엄 팩을 되살린다
