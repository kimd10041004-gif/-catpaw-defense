# 확장 가이드

이 게임의 콘텐츠는 전부 **데이터**다. 아래 작업 중 어떤 것도 `game.js` / `render.js` / `ui.js`를 고치지 않는다.

무엇을 추가하든 마지막에 이것만 돌리면 된다:

```bash
npm test
```

`content.test.mjs`가 참조 무결성·밸런스 곡선을 다시 검사하고, 게임을 열면 `validateAll()`이 부팅 때 한 번 더 검사한다.
오타가 나면 조용히 깨지지 않고 **한국어 에러 메시지**가 타이틀 화면에 그대로 뜬다.

## 1. 새 고양이(타워) 추가

`web/js/content/towers.js` 맨 아래에 블록 하나를 붙인다.

```js
registerTower({
  id: 'ninja',                 // 다른 타워와 겹치면 ContentError
  name: '닌자냥',
  order: 6,                    // 상점·도감 정렬 순서
  desc: '그림자에서 표창을 던진다. 사거리는 짧지만 연사가 매우 빠르다.',
  sprite: 'cat',               // sprites.js에 등록된 키
  targets: 'all',              // 'all' | 'ground' | 'air'
  palette: { fur: '#3d4a5c', belly: '#93a3b8', stripe: '#2a3441', eye: '#ff6b6b' },
  levels: [
    // levels[0].cost = 건설비 / 나머지 cost = 그 레벨로 올리는 업그레이드비
    { cost: 150, damage: 9,  range: 2.0, fireRate: 3.2, projectile: 'dart', effects: [] },
    { cost: 110, damage: 15, range: 2.2, fireRate: 3.8, projectile: 'dart', effects: [] },
    { cost: 220, damage: 24, range: 2.4, fireRate: 4.4, projectile: 'dart', effects: [] },
  ],
})
```

끝이다. 상점 카드, 도감 항목, 업그레이드 패널, 사거리 표시가 전부 자동으로 생긴다.

| 필드 | 단위 / 규칙 |
|---|---|
| `range` | 타일 |
| `fireRate` | 발/초 |
| `damage` | 1발당. 적 방어력만큼 깎이고 **최소 1은 들어간다** |
| `projectile` | `'pellet'`·`'bomb'`·`'gaze'`·`'dart'` 또는 `null`(즉시 타격) |

> 테스트가 **레벨이 오를수록 DPS가 증가**하는지 검사한다. `damage × fireRate`가 단조 증가해야 한다.

| 축 | 해충 |
|---|---|

게임이 멈춘다.

## 3. 새 스프라이트(그림) 추가

`web/js/sprites.js`에 그리는 함수를 만들고 등록한다.

```js
function drawWasp(ctx, o) {
  const { x, y, r, palette: p, angle = 0, t = 0 } = o
  ctx.save()
  ctx.translate(x, y)
  // ... 캔버스 프리미티브로 그린다 (이미지 파일은 쓰지 않는다)
  ctx.restore()
}
registerSprite('wasp', drawWasp)
```

계약: `x, y`는 화면 픽셀 중심, `r`은 픽셀 반지름, `angle`은 바라보는 방향(라디안), `t`는 경과 시간(초, 애니메이션용).
함수는 **스스로 `save`/`restore`** 해야 하며 호출자의 변환 상태를 바꾸면 안 된다.

## 3-b. 프레임 아트(그림 파일)로 캐릭터 갈아끼우기

캔버스로 그린 벡터 대신 채색 그림을 쓴다. **그림이 없으면 자동으로 벡터로 떨어지므로
한 캐릭터씩 넣어도 된다.**

### 그림 규격

가로로 프레임을 붙인 스트립 한 장. 프레임 수는 종류마다 다르다.

**고양이 — 5장** (`169×169` × 5 = `845×169`)

| 프레임 | 뜻 | 언제 |
|---|---|---|
| 0 | 발사 순간 | `recoil >= 0.82` |
| 1 | 되돌아오는 중 | `>= 0.48` |
| 2 | 거의 제자리 | `>= 0.15` |
| 3 | 대기 | 그 아래 |
| 4 | 자는 중 | 5초 넘게 안 쏘면 |

**해충 — 3장** (`209×209` × 3 = `627×209`)

| 프레임 | 뜻 | 언제 |
|---|---|---|
| 0 | 걷기 A | 초당 6회 B와 번갈아 |
| 1 | 걷기 B | 〃 |
| 2 | 멈춤 | 속도 배율 0.5 이하 (자장가 등) |

해충에 피격·죽음 프레임은 요청하지 않는다. 피격 번쩍임은 `ctx.filter` 로,
보호막·광폭화 고리·엘리트 왕관은 코드가 그린다. 안 쓸 프레임을 빼면 같은 가로
폭에서 칸이 커진다 = 그림이 커진다.

- **PNG-32, 배경 완전 투명**
- **오른쪽을 보게** 그린다. 타깃이 왼쪽이면 코드가 통째로 좌우 반전한다
- **방향성 효과(칼·룬 원·속도선·잔상)는 그림에 넣는다.** 반전으로 방향이 맞춰지고,
  코드가 회전 효과를 덧그리면 이중으로 보인다
- **바닥 그림자도 그림에 넣는다.** 그림을 쓰면 코드가 그림자를 그리지 않는다

### 등록

`web/js/framesets.js`:

```js
registerFrameSet('cat-newcat', {
  src: 'art/cat-newcat.png',
  frames: 5, w: 169, h: 169,
  body: { cx: 82, cy: 73, h: 107 },   // ★ 대기 프레임에서 고양이가 차지하는 영역
})
```

`body` 를 왜 주는가: 그림 안에서 캐릭터가 프레임을 꽉 채우지 않는다. 이 값이 없으면
벡터에서 그림으로 바꿀 때 크기와 바닥 위치가 어긋난다. 실측값은
`tools/slice-sheet.mjs` 가 표로 출력한다. 고양이 5마리는 모두 같은 값이라
`CAT` 상수를 공유한다.

선택 항목 세 개:

| 항목 | 뜻 | 언제 쓰나 |
|---|---|---|
| `hPerR` | 이 캐릭터가 화면에서 쓰는 세로 폭 (반지름 r 배수) | 생쥐 1.85 · 흡혈 박쥐왕 1.49 처럼 캐릭터마다 다르다. 안 주면 고양이 기준(2.18)이라 해충이 전부 고양이 크기로 나온다 |
| `cyPerR` | 같은 기준의 세로 중심 | 〃 |
| `shadow` | `{ cy, rx, ry, alpha }` — 코드가 그릴 바닥 그림자 | **그림에 그림자가 없을 때만.** 보스 시트가 그 경우다 |

`hPerR`/`cyPerR` 은 눈대중이 아니라 실측한다. 스프라이트를 오프스크린 캔버스에 그리고
알파 경계를 재면 된다. 바닥 그림자는 `globalAlpha 0.26` 으로 그려지므로 **알파 200
이상만 세면 몸만** 잴 수 있다.

그리고 타워 정의(`content/towers.js`)에 한 줄:

```js
registerTower({ id: 'newcat', sprite: 'cat', pose: 'jab', frames: 'cat-newcat', ... })
```

- `frames` 를 빼면 지금까지처럼 벡터로 그려진다
- 그림에 없는 효과를 코드로 덧그려야 하면 `effectOverArt: true` 를 준다
  (샴냥이 유일한 예 — 그림에 눈빛이 없어서 `gaze` 포즈의 효과만 얹는다)
- 오타는 부팅 때 `validateAll()` 이 잡고 등록 방법과 쓸 수 있는 목록을 알려준다
- **`web/sw.js` 의 `ASSETS` 에 `art/...png` 를 넣고 `CACHE_VERSION` 을 올린다**
  (§11 참조 — `tests/node/sw.test.mjs` 가 빠뜨림을 잡는다)

### 알파 없는 시트에서 잘라 쓸 때

`tools/slice-sheet.mjs` 가 `art-src/pose-sheet-cats.png`(5×5 격자, 배경 불투명)에서
`web/art/cat-*.png` 를 굽는다. 배경을 파내는 방식이 단순 임계값이 **아니다**:

1. 셀별 지역 배경을 링 중앙값으로 추정 (배경이 60~68로 평탄하지 않다)
2. 배경과의 차이로 알파 램프
3. **가장자리에서 flood fill 해 배경과 이어진 곳만 지운다** — 뚱냥의 회색 먼지·잔상이
   배경색과 가까워서, 값으로만 판단하면 통째로 사라진다
4. 배경값과 같은 픽셀 중 **200px 이상 뭉친 덩어리**는 둘러싸여 있어도 배경으로 인정
   — 삼색냥 룬 원 안쪽이 불투명한 검은 원반으로 남는 것을 막는다. 크기 조건이 없으면
   검은냥의 회색 털 하이라이트까지 뚫려 몸에 구멍이 난다
5. 언프리멀티플라이로 회색 띠 제거

시트가 늘어나서 격자·키잉 설정은 파일 맨 위 `SHEETS` 표로 뺐다. 시트마다 다른 값:

| 항목 | 뜻 |
|---|---|
| `cols`/`rows`/`size`/`ring` | 격자 좌표와 셀 크기, 테두리선을 지울 폭 |
| `lo`/`hi`/`fillT` | 알파 램프 시작·끝, flood fill 이 통과할 수 있는 차이 |
| `aaRadius` | 실루엣에서 이만큼 넘게 떨어진 배경은 무조건 투명 |
| `dropSmallParts` | 캐릭터와 이어지지 않은 작은 덩어리를 지운다 (셀에 찍힌 프레임 번호 등) |
| `masks` | 시트 좌표로 지정해 지울 영역 (발주서 안내 문구 등) |
| `shadow` | 그림자가 지워지는 시트라는 표시 — 프레임셋에 `shadow` 를 함께 준다 |

**보스 시트가 왜 다른 설정을 쓰나**: 그 시트만 캐릭터 뒤에 푸른 후광이 깔려 나왔다.
기본 설정으로는 후광이 검은 원반처럼 통째로 남는다. 실측하니 후광은 배경차이 12~48 ·
저채도이고 캐릭터 몸은 60 이상이라, **fill 이 후광을 통과하도록 `fillT` 를 45 로 올리고
알파 램프는 `hi` 22 로 좁게 둔 뒤, 실루엣에서 2px 넘게 떨어진 곳은 아예 투명**으로
만들었다. 그 과정에서 구워진 바닥 그림자도 지워지므로 프레임셋에 `shadow` 를 준다.

**작은 덩어리 필터가 위치 기반 마스킹보다 나은 이유**: 셀마다 프레임 번호가 찍혀
나왔는데, 위쪽 N% 를 잘라내면 마왕 쥐의 뿔이 같은 높이라 같이 날아간다. 글자는
캐릭터와 이어지지 않은 작은 덩어리이므로 '가장 큰 덩어리의 4% 미만'으로 거른다.
단, 글자끼리 붙어 하나의 긴 덩어리가 되면 이 필터를 통과한다 — 일반 해충 시트의
안내 문구가 그랬고, 그건 `masks` 로 좌표를 찍어 지웠다.

투명 배경 원본이 오면 `--keep-alpha` 로 이 과정을 건너뛴다.
결과 확인은 `tools/out/14-slice-check.png`(체커보드 격자)와
`tools/out/12-poses.png`(게임과 같은 `drawUnit` 으로 그린 모션 시트).

## 4. 새 능력(effect) 추가

> **`name` 과 `describe(spec)` 은 필수다.** `registerEffect('이름', { name: '둔화', describe: (fx) => \`${fx.factor*100}% / ${fx.duration}초\`, onHit… })`
> 처럼 화면 문구를 핸들러에 같이 둔다. 타워 패널과 도감이 `describeEffect(fx)` 로 이걸 읽는다 — 전에는 패널이 세 가지만 알아서
> 나중에 붙은 효과 4종이 설명 없이 팔렸다. 없으면 등록 자체가 거부된다.

`web/js/content/effects.js`에 핸들러를 등록하고, 타워 레벨의 `effects`에 넣는다.

```js
registerEffect('burn', {
  onHit(ctx, fx, target) {
    // fx = 타워 데이터에 쓴 객체 그대로: { kind:'burn', dps:8, duration:3 }
    ctx.applyDamage(target, fx.dps)
    ctx.spawnParticle(target.x, target.y, { kind: 'hit', color: '#ff8a3d' })
  },
})
```

```js
// towers.js — 그 다음 이렇게 쓴다
{ cost: 200, damage: 20, range: 2.5, fireRate: 1.0, projectile: 'pellet',
  effects: [{ kind: 'burn', dps: 8, duration: 3 }] },
```

**핸들러 계약**

| 훅 | 호출 시점 | 반환 |
|---|---|---|
| `onFire(ctx, fx, target)` | 발사 순간 | `{ consumed: true }`를 주면 투사체를 만들지 않는다 (뚱냥의 광역기가 이 방식) |
| `onHit(ctx, fx, target)` | 투사체 명중 순간 | 무시됨 |

`ctx`로 쓸 수 있는 도구:

```
ctx.tower                            발사한 타워 (타일 좌표, range, targets)
ctx.now                              게임 내부 시각(초)
ctx.damage                           이번 발사의 기본 공격력
ctx.enemies                          살아 있는 적 배열
ctx.applyDamage(enemy, amount)       방어력 적용 후 피해 (처치·골드 정산 포함)
ctx.applyTrueDamage(enemy, amount)   방어력을 무시하는 피해
ctx.addDot(enemy, dps, sec, 최대스택) 지속 피해 한 스택 (장갑 무시, 상한 있음)
ctx.enemiesInRadius(x, y, r, opts)   반경 내 적. opts.exclude / opts.targets
ctx.addSlow(enemy, factor, sec)      적 저항을 반영한 슬로우
ctx.spawnParticle(x, y, opts)        연출
ctx.playSfx(name)                    효과음
```

**지금 등록된 능력 7종**: `splash` · `slow` · `aura` · `dot` · `chain` · `pierce` ·
`buff`(passive).

### 쏘지 않는 능력 — `passive: true`

`buff`(턱시도냥)는 발사와 아무 상관이 없다. 옆 고양이를 강하게 만드는 성질이라
`domain/mods.js` 의 `towerModsFor` 가 파라미터를 직접 읽는다. 그래도 **등록은 해야
한다** — `validateAll()` 이 타워의 `effects[].kind` 가 등록된 것인지 검사하기 때문이다.

```js
registerEffect('buff', { passive: true })   // onHit/onFire 가 없어도 통과한다
```

`passive` 없이 빈 객체를 넘기면 부팅이 막힌다. 그게 맞다 — 훅을 빠뜨린 실수와
일부러 훅이 없는 능력을 구별할 방법이 그것뿐이다.

### 배수는 어디서 곱하는가 — `domain/mods.js` 한 곳

펫 · 고양이 조합 · `buff` 고양이는 전부 "어떤 타워의 숫자를 올린다"를 한다.
각자 곱하면 서로를 모른 채 겹쳐서 곱이 터지므로 **한곳에서 합치고 상한을 씌운다**
(`damageMul ≤ 2.5 · fireRateMul ≤ 2.0 · rangeAdd ≤ 1.5`).

```js
tower.mods = towerModsFor(tower, towers, combos, matchCombo)   // { damageMul, fireRateMul, rangeAdd, ... }
```

**매 프레임 부르지 않는다.** 배치·업그레이드·판매로 타워 집합이 바뀔 때만
`game.recomputeTowerMods()` 가 다시 계산해 `tower.mods` 에 얹어 둔다.

등록하지 않은 `kind`를 타워에 쓰면 부팅 때 이렇게 막힌다:

```
타워 'x' 레벨 1이(가) 등록되지 않은 효과 'burn'을(를) 참조합니다.
content/effects.js에 registerEffect('burn', ...)를 추가하세요.
```

## 5-b. 지도 아트(길 질감 · 막힌 칸 소품)

캐릭터 아트와 같은 규칙이다 — **그림이 없으면 지금의 단색 렌더링으로 조용히 떨어진다.**
한 맵씩 넣어도 되고, 오타는 부팅 때 걸린다.

### 핵심: 기하는 한 글자도 안 바꾼다

`fillStyle` / `strokeStyle` 은 색뿐 아니라 `CanvasPattern` 도 받는다. 그래서 길에
질감을 입힐 때 **폴리라인을 건드리지 않는다** — 색을 넣던 자리에 패턴을 넣을 뿐이다.

```js
const pat = getPathPattern(game.mapDef.id, ctx, t, this.ox, this.oy)
ctx.strokeStyle = pat || game.mapDef.theme.path   // 패턴이 없으면 단색
ctx.lineWidth = t * 0.78
ctx.stroke()
```

이렇게 하면 **길 그림과 실제 경로가 어긋나는 사고가 구조적으로 불가능하다.** 통짜
배경 일러스트에 길을 그려 넣는 방식은 이 보장이 없다(실제로 그렇게 받아 봤더니
맵 하나는 실제 경로와 36%밖에 안 겹쳤다).

격자에 맞추는 건 패턴 변환이 한다:

```js
pattern.setTransform(new DOMMatrix().translate(ox, oy).scale(tile * PATCH_TILES / img.width))
```

`PATCH_TILES` 는 질감 한 장이 몇 칸을 덮는지다(지금 2). 화면 크기가 바뀌면 `tile` 과
`ox/oy` 가 달라지므로 패턴을 다시 만든다 — 성능 때문이 아니라(실측 2.3µs) 캐시 키를
`tile|ox|oy` 로 두는 편이 단순해서다.

### 새 질감·소품 등록

`web/js/mapart.js`:

```js
registerMapArt('basement', { path: 'art/path-basement.png' })
registerProp('barrel', { src: 'art/prop-barrel.png' })
```

- `registerMapArt` 는 `path`(길 질감) 또는 `floor`(바닥 질감) 중 하나 이상이 필요하다
- 소품은 **알파 경계를 자동 실측**한다(`solidBounds`). 그림이 칸을 꽉 안 채워도
  바닥에 발이 닿게 놓이므로, 새 소품을 넣을 때 좌표 상수를 적을 필요가 없다
- 막힌 칸이 여럿이면 `(열 + 행) % props.length` 로 번갈아 놓는다 — 같은 그림이
  나란히 붙는 걸 줄인다
- 로드 완료 콜백이 필요 없다. 캔버스는 매 프레임 다시 그리므로 늦게 와도 다음
  프레임에 반영된다

### 시트에서 굽기

`tools/slice-sheet.mjs` 의 `SHEETS` 표에 시트를 더한다. 캐릭터 시트와 두 가지가 다르다:

| 옵션 | 뜻 |
|---|---|
| `raw: true` | 파낼 배경이 없다 — 자르기만 한다 (길 질감은 셀 전체가 그림이다) |
| `perCell: true` | 한 행이 한 캐릭터의 프레임 묶음이 아니라, **칸 하나가 각각 독립된 그림**이다 |

`perCell` 이 없으면 3열짜리 지도 시트가 "3장이 가로로 이어붙은 스트립" 하나로 나온다.

굽고 나면 반드시 체커보드 확인 이미지를 **눈으로 본다** (`14-slice-check-paths.png`,
`14-slice-check-props.png`). 지금까지 슬라이스 사고는 전부 여기서 잡혔다.

### 그림을 발주할 때 — 시트에 넣으면 안 되는 것

생성 도구는 **전체 출력 크기가 대체로 고정**(640~830px)이다. 칸을 나눌수록 칸당
해상도가 무너진다. 그래서:

- **시트로 받는다**: 질감 · 소품 · 캐릭터 프레임 — 작아도 되는 것
- **한 장씩 따로 받는다**: 화면을 꽉 채우는 그림(타이틀 배경 등)

한 시트에 전체화면 배경 3장을 넣어 달라고 했다가 186×286 으로 받은 적이 있다.
1152×1792 로 쓰려면 6.2배 확대라 못 썼다.

`tools/map-spec.mjs` 가 발주서 이미지를 만든다.

같은 파일의 `DIFFICULTIES`에 넣으면 설정의 난이도 선택지에 자동으로 나타난다.

## 9-b. 시나리오 챕터 추가

`web/js/content/scenario.js` 에 블록을 하나 더 쓴다. 맵을 새로 만들 필요는 없다 —
`waveSet` 과 `waveLimit` 으로 기존 맵의 길이와 성격을 바꾼다.

```js
registerChapter({
  id: 'ch13', order: 13, title: '새 장',
  mapId: 'basement', waveSet: 'swarm14', waveLimit: 10,   // waveLimit 은 선택
  primary: { kind: 'survive' },
  bonus: [{ kind: 'noLeak' }, { kind: 'maxTowers', n: 8 }],   // 최대 2개 (별이 3개다)
  intro: [{ who: 'cheese', text: '또야?' }],
  outro: [{ who: 'cheese', text: '끝.' }],
  rewards: { catnip: 30, tower: 'newcat' },                   // tower · pet 은 선택 (첫 클리어에 한 번)
  act: 2,                                                     // 막 번호 (선택, 기본 1) — 목록에 '2막' 제목이 생긴다
})
```

**유료 막**: `act: 3` 처럼 `FREE_ACTS`(1·2) 밖의 막은 `progress.unlocks.acts` 에 번호가 있어야 열린다(`isChapterUnlocked` 가
`hasAct` 를 본다). 파는 상품은 `shop.js` 의 `grants: { act: 3 }`. 챕터 목록은 안 산 막을 `유료` 배지로 그리고 누르면 상점을 연다.
업적 `scenario-done`/`scenario-perfect` 는 무료 막만 센다 — 안 사면 영영 못 푸는 업적을 만들지 않는다.

`Game` 은 `waveSet`/`waveLimit` 두 옵션만 받는다:

```js
this.waveTable = getWaveSet(waveSet || mapDef.waveSet)
this.totalWaves = waveLimit > 0 ? Math.min(full, waveLimit) : full
```

승리 판정·진행률·다음 웨이브 버튼이 전부 `totalWaves` 를 보므로 새 분기가 없다.

부팅 때 `validateAll()` 이 확인하는 것: 맵·웨이브셋이 등록됐는지, 목표 kind 가
등록됐는지, 목표에 필요한 항목(`n`, `ids`, `enemyId`, `comboId`)이 채워졌는지, 보상 타워·펫이
있는지, 컷신 화자가 타워나 적 중 하나인지, `order` 가 겹치지 않는지,
`waveLimit` 이 웨이브셋 길이를 넘지 않는지. `content.test` 가 장 수와 `order` 1..n 연속을 함께 본다.

```js
  requires: ['n'],                                    // 챕터가 반드시 채워야 할 항목
  label: (spec) => `골드 ${spec.n} 이상 모으기`,
  check: (summary, spec) => summary.goldEarned >= spec.n,
})
```

### `summary` 에 없는 값이 필요하면 — 두 종류가 있고 함정이 다르다

`summary()` 는 `...this.stats` 를 펼쳐 보낸다. 그래서:

| 어디에 있나 | 무엇을 해야 하나 | 예 |
|---|---|---|
| `this.stats` 안 | **집계만 더하면 자동으로 따라온다** | `towersSold` · `upgradesBought` |
| `this.stats` 밖 | **`summary()` 에 직접 써야 한다** | `goldLeft`(`this.gold`) · `elapsed`(`this.time`) |

두 번째를 빠뜨리면 목표가 `undefined` 를 보고 **조용히 '항상 통과'** 가 된다.
실행 검증에 "집계 4종이 판 결과에 실려 나온다"가 있는 이유다 —
`summary()` 에서 두 줄을 지우면 실제로 실패한다.

`Set` 을 쓴다면 `summary()` 에서 배열로 굳혀야 `JSON.stringify` 에서 `{}` 가 되지
않는다 (`towerIdsUsed` 가 그 예다).

### 지금 등록된 목표 14종

`survive` · `killBoss` · `noLeak` · `livesAbove` · `maxTowers` · `onlyTowers` ·
`withoutTowers` · `maxSpecials` · `noSell` · `goldLeft` · `noUpgrade` ·
`clearWithin` · **`makeCombo`**(`comboId`, 그 조합을 판 중에 한 번이라도) · **`killAtLeast`**(`n`)

`clearWithin` 은 `cleared === true` 를 함께 본다. 30초 만에 뚫린 판이 "빨랐다"고
통과하면 안 되기 때문이다.

판정 자체는 순수 모듈 `domain/objectives.js` 의 `evaluateObjectives()` 가 돌린다.
주 목표를 못 지키면 부 목표를 다 채워도 별이 0개다.

## 10. 저장 데이터 구조를 바꿀 때

`web/js/domain/save.js`에서 `SAVE_VERSION`을 올리고 `migrate()`에 단계를 이어 붙인다.
기존 사용자의 저장 데이터가 깨지지 않게 하는 유일한 방법이다.

```js
export const SAVE_VERSION = 7   // 지금은 6 — 올릴 때마다 +1

// migrate() 안, v5 → v6 블록 다음에
if (version < 7) {
  cur = { ...cur, version: 7, 새필드: 기본값 }
  migrated = true
}
```

각 버전이 무엇을 넣었는지는 `save.js` 의 `defaultProgress()` 주석에 있다(v5: hintsSeen · stats · achievements ·
daily · endless · challenge, v6: growth · skins · unlocks · weekly). `tests/node/save.test.mjs` 의 `v5 → v6` 무손실·멱등·
왕복·정리 검사를 복사해 다음 버전에도 같은 검사를 쓴다 — 마이그레이션이 값을 조용히 떨어뜨리는 사고를 잡는 유일한 그물이다.
새 필드마다 정리 함수(`sanitizeGrowth` 처럼 범위를 자르고 모르는 값을 버리는)를 쓴다.

**★ 마지막 정규화 단계(`const progress = { ... }`)에도 새 필드를 반드시 넣는다.**
안 넣으면 마이그레이션은 통과하는데 값이 조용히 사라진다. 저장·불러오기를 왕복하는
테스트를 같이 쓰면 이 실수를 바로 잡는다.

읽을 수 없는 데이터(깨진 JSON, 더 최신 버전)는 **지우지 않고** `catpaw.progress.backup` 키로 옮긴 뒤 기본값으로 시작한다.

## 12. 새 보스 능력 추가

> **`name` 과 `describe(ab)` 은 필수다.** 도감의 해충 항목과 보스 등장 배너가 `describeAbility(ab)` 로 읽는다.
> 파라미터를 보간해서 쓴다 — 수치를 바꾸면 문장도 따라온다.

`web/js/content/enemyAbilities.js`에 핸들러를 등록하고, `enemies.js`의 `abilities`에 넣는다.

```js
registerEnemyAbility('teleport', {
  onTick(ctx, ab, e) {
    if (ctx.now < (e.nextBlink || 0)) return
    e.nextBlink = ctx.now + (ab.every || 8)
    e.progress += ab.distance || 2          // 앞으로 순간이동
    ctx.spawnParticle(e.x, e.y, { kind: 'summon', color: '#c084fc', radius: 1 })
  },
})
```

```js
// enemies.js — 그 다음 이렇게 쓴다
abilities: [{ kind: 'teleport', every: 8, distance: 2 }],
```

**훅 계약**

| 훅 | 호출 시점 | 반환 |
|---|---|---|
| `onSpawn(ctx, ab, e)` | 등장 순간 | 무시됨 (상태 초기화용) |
| `onTick(ctx, ab, e, dt)` | 매 시뮬레이션 스텝 | 무시됨 |
| `onDamaged(ctx, ab, e, dmg)` | 피해 직전 | **숫자를 반환하면 그 값으로 대체**된다 (보호막이 이 방식) |
| `onDeath(ctx, ab, e)` | 사망 순간 | 무시됨 (분열이 이 방식) |

`ctx`로 쓸 수 있는 도구:

```
ctx.now, ctx.enemies
ctx.spawnMinion(enemyId, { progress, hpMul })   부하 소환
ctx.enemiesInRadius(x, y, r, { exclude })
ctx.spawnParticle(x, y, opts), ctx.addFloater(x, y, text, color)
ctx.playSfx(name), ctx.flash(color, strength), ctx.shake(amount)
```

**스탯 보정 규약**: 능력은 매 스텝 0으로 초기화되는 `e.auraArmor` / `e.auraSpeed` 에만 쓴다.
`e.def`를 직접 고치면 그 정의가 다음 판까지 오염된다 — 절대 하지 않는다.

> 등록하지 않은 kind를 쓰면 부팅 때 `registerEnemyAbility('teleport', ...)를 추가하세요` 라고 알려준다.

판이 끝날 때만 기록하면 중간에 나간 사람이 발견을 잃는다.

## 13-g. 도전 추가 (규칙 하나 얹기)

`web/js/content/challenges.js` 에 블록 하나. 깬 자유 모드 맵의 카드에 `도전 n/m` 칩이 생기고

## 13-h. 스킨 추가 (겉모습만)

`web/js/content/skins.js` 에 블록 하나. 도감 고양이 행의 `스킨` 칩과 스킨 시트가 레지스트리를 순회한다.

```js
registerSkin({
  id: 'cheese-ember', towerId: 'cheese', order: 2, name: '잉걸 치즈냥', desc: '불씨 색으로 달아오른 치즈냥.',
  look: { filter: 'hue-rotate(-18deg) saturate(1.6)' },   // 그림 없이 — 프레임 스트립을 CSS 필터로 한 번 굽는다
  price: 120,                                             // 캣닢. IAP 팩이면 sku: 'skin_pack_1', 보상 전용이면 둘 다 없음
})
```

- **능력치는 없다.** `mods` 를 주면 등록 때 던진다. 약속이다(`content.test`).
- `look.filter` 스킨은 `framesets.js getFrameImage(key, skin)` 이 첫 사용 때 스트립 전체를 오프스크린 캔버스에 구워 캐시한다 —
  프레임마다 필터를 걸지 않는다. `ctx.filter` 를 모르는 브라우저면 원본을 쓴다(오류 없음). 벡터 폴백(그림 없는 환경)엔 안 보인다.
- **그림 스킨**은 `look: { frames: 'cat-cheese-armor' }` — `registerFrameSet('cat-cheese-armor', { src, ...CAT })` 으로 원본과
  **같은 격자(frames·w·h)** 의 프레임셋을 먼저 등록한다. `validateAll` 이 격자를 대조한다. 발주서: `docs/발주서-스킨.md`.
- 장착은 판 밖(도감)에서 하고 `placeTower` 가 `tower.skin` 에 굳힌다. 상점 카드·도감·타워 패널의 `spriteCanvas(def, size, skin)` 이 같은 경로를 쓴다.
- 챕터 보상으로 주려면 `rewards: { skin: 'black-midnight' }` — `recordChapter` 가 첫 클리어에 한 번 `skins.owned` 에 넣는다.

## 16. 문구와 번역 (영어)

문구는 **한국어 원문이 곧 사전 키**다. 영어는 `web/js/i18n/en.js` 하나이고, 언어는 부팅 때 한 번 정해진다(`main.js` App 생성자 —
`resolveLanguage(설정, navigator.language)` → `localizeStatic(document)` → `registry.localizeAll(tr)`).

세 가지 자리가 있다.

```js
// 1) 실행 때 만드는 문구 — tr 로 감싼다. {이름} 자리는 vars 로. 템플릿 리터럴은 쓰지 않는다(문장이 완성돼 키가 될 수 없다).
import { tr } from './i18n/index.js'
this.ui.toast(tr('{name} 훈련 {rank}단계', { name: def.name, rank }))

// 2) 콘텐츠 정의의 이름·설명·배지·챕터 제목·컷신 대사 — 그대로 둔다. registry.localizeAll(tr) 이 부팅 때 제자리에서 바꾼다.
registerPet({ id: 'ferret', name: '족제비', desc: '…' })

// 3) 부팅 전에 평가되는 모듈 상수 표(배치 실패 사유 · 상품 목록 · 설정 스키마 · 힌트) — 값은 키로 두고 표시하는 쪽이 tr(표.값) 으로 감싼다.
//    wrap 파일 안이면 그 줄에 // i18n-key 를 붙이거나 // i18n-keys:start … // i18n-keys:end 로 감싼다.
```

새 문구를 넣었으면 `en.js` 에 같은 키로 영어를 넣는다. 복수형처럼 치환만으로 안 되면 값을 함수로 쓴다:
`'{v}판': ({ v }) => \`${v} ${v === 1 ? 'run' : 'runs'}\``.

```
node tools/i18n-scan.mjs        # 감싸지 않은 한글 · 한글 템플릿 · 누락 · 미사용 · 자리표시자 불일치 · 영어 값의 한글
```

`tests/node/i18n.test.mjs` 가 위 여섯 가지가 전부 0 인지 검사한다. 파일 목록(`FILES`)은 도구 상단에 있다 — 사용자용 파일만 보고,
레지스트리 오류·도구·검사 같은 개발자용 문구는 보지 않는다. 새 사용자용 파일을 만들면 목록에 넣는다.
`index.html` 의 정적 문구는 `data-i18n`(텍스트 노드) · `data-i18n-attr="title,aria-label"`(속성) 표시로 같은 사전을 쓴다.

스모크의 영어 패스(`tools/screenshot.mjs`)가 기기 언어 영어로 부팅해 로딩·타이틀·맵·게임·설정·도감·상점·결과의 화면 텍스트에
한글이 없는지 본다 — 사전에 없는 문구는 한국어로 새고(정직한 폴백), 그걸 눈이 아니라 이 검사가 잡는다.
새 언어를 더하려면 `i18n/index.js` 의 `LANGUAGES`·`DICTS` 와 설정 `language` 의 선택지에 한 줄씩이다.

## 17. 공식 사이트 (`site/`)

받아 가는 곳 한 장. **게임(`web/`)은 여기 안 올린다** — 웹 빌드는 '데모 결제'라 3막·스킨까지 결제 없이 열리기 때문이다.
그래서 `site/` 는 게임 코드를 하나도 import 하지 않는 독립된 정적 파일이다.

```
site/index.html      손으로 쓴 한 장 (스타일 인라인, 스크립트 없음)
site/img/            tools/site-build.mjs 가 store/ 에서 구워 넣는다 — 커밋한다
.github/workflows/pages.yml   main 의 site/**·web/** 푸시마다 굽고 gh-pages 브랜치로 밀어 배포
```

무엇을 고칠 때 무엇을 하나:

| 고치는 것 | 하는 일 |
|---|---|
| 문구·구성 | `site/index.html` 을 직접 고친다. 빌드 단계가 없다 |
| 스크린샷 | `tools/store-assets.mjs` 로 `store/` 를 다시 굽고 → `node tools/site-build.mjs` (540×960 으로 줄여 `site/img/` 에) → 둘 다 커밋 |
| 버전 | 건드리지 않는다. `node tools/bump-version.mjs` 가 푸터의 `<span class="ver">v1.0.0</span>` 도 같이 올린다 |
| 다운로드 주소 | 건드리지 않는다. `release.yml` 이 올리는 **버전 안 박힌 별칭** `catpaw-defense-latest.apk` 를 건다 — 버전을 올려도 링크가 안 죽는다 |

`tests/node/site.test.mjs` 가 보는 것: 참조한 그림이 실제로 있나 · 여덟 장을 다 걸었나 · 다운로드 링크가 `latest` 별칭인가 ·
버전이 `package.json` 과 같은가 · **"아이폰용 앱은 없다"와 "정직하게 실패한다"가 사이트에 적혀 있나**.
마지막 것은 `content.test` 의 "유료가 무료를 잠그지 않는다"와 같은 결이다 — 약속을 사람 기억이 아니라 검사가 지킨다.

개인정보처리방침은 같은 도구의 다른 스위치다:

```
node tools/site-build.mjs --privacy      # docs/개인정보처리방침.md → site/privacy.html
```

`[연락처]`·`[출시일]` 같은 **자리표시자가 남아 있으면 만들지 않고 exit 1** 한다(`findPlaceholders`).
마크다운 → HTML 은 `miniMarkdown` 이 한다 — 제목·표·목록·굵게·코드·링크만 아는 60줄짜리다.
라이브러리를 안 들이는 이유는 이 저장소의 의존성이 0이기 때문이다.

**Pages 는 `gh-pages` 브랜치로 켜져 있다 — 사람이 누른 적이 없다.**

처음엔 `actions/deploy-pages` 로 하려 했는데 못 켰다: Pages **사이트 생성**은 admin 권한이라
`GITHUB_TOKEN` 으로 안 된다(`Get Pages site failed ... Not Found`, `enablement: true` 로도
`Resource not accessible by integration`). 그래서 Settings 에서 사람이 바꿔야 하는데 그게 여러 번 막혔다
(모바일 앱에는 Pages 설정 항목이 없고, 로그아웃 상태면 설정 페이지가 404 로 보인다).

그런데 GitHub 은 **`gh-pages` 브랜치가 올라오면 Pages 를 자동으로 켠다** — 설정 API 를 안 지나므로 권한 문제가 없다.
그래서 워크플로는 구운 `site/` 를 그 브랜치에 통째로 덮어쓰기만 한다(이력은 안 쌓는다 — 8.5MB 라 커진다).

- `gh-pages` 는 **산출물 브랜치다.** 손으로 고치지 않는다 — `main` 을 고치면 워크플로가 다시 민다.
- 배포 스텝에 `play/index.html` 이 커밋에 들어갔는지 보는 검사가 있다. 루트 `.gitignore` 의 `site/play/` 가
  닿으면 **아이폰 경로만 조용히 빠진 사이트**가 올라가기 때문이다(지금은 안 닿는다 — 새 저장소의 루트가 `site/` 라서).
- 저장소를 **Private 으로 바꾸면 Pages 가 끊긴다**(GitHub Pro 필요). 그때는 Vercel 로 간다 —
  루트의 `vercel.json` 이 그 준비고, 같은 검사·같은 빌드 명령을 쓴다.

## 18. 유료 콘텐츠를 더할 때 — 데모 빌드가 있다

공식 사이트에는 **유료 콘텐츠를 뺀 브라우저판**(`site/play/`)이 같이 올라간다. 아이폰이 APK 를 못 깔아서
그게 유일한 길인데, `web/` 을 그대로 올리면 웹의 '데모 결제'가 3막·스킨 팩을 공짜로 열어 버린다.
그래서 **파는 물건은 데모에 아예 안 싣는다.** 자세한 배경은 [`아이폰.md`](아이폰.md).

**그래서 규칙 하나가 는다: 유료 콘텐츠는 무료 콘텐츠와 같은 파일에 쓰지 않는다.**

```js
// web/js/content/index.js
import './challenges.js'       // 무료
import './challenges-pack2.js' // 유료               // demo:strip   ← 이 표시가 전부다
```

`tools/demo-build.mjs` 가 `// demo:strip` 이 붙은 import 줄을 지우고 그 파일을 안 옮긴다.
지금 그렇게 나가 있는 셋:

| 파일 | 무엇 | 파는 상품 |
|---|---|---|
| `content/scenario-act3.js` | 시나리오 19~24장 | `story_act3` |
| `content/challenges-pack2.js` | 도전 5종 | `challenge_pack2` |
| `content/skins-paid.js` | 스킨 8종(팩 7 + 24장 보상 1) | `skin_pack_1` · `skin_pack_2` · `starter_pack` |

상품 목록 자체(`domain/shop.js` 의 `IAP_PRODUCTS`)도 데모에선 빈 배열이 된다 —
`// demo:empty-start` … `// demo:empty-end` 사이를 갈아 끼운다. 살 수 없는 목록을 진열하지 않는다.

`web/js/build.js` 는 통째로 갈린다(`DEMO = true`) → `billing.js` 가 `DisabledBillingProvider` 를 골라
구매를 그 자리에서 거절하고, `ui.openStore` 가 상품 대신 "전체판은 안드로이드 앱에서" 한 칸을 보인다.

**안 빼는 것도 있다.** 웨이브셋(`gauntlet20`·`mixed25`)은 지금 3막만 쓰지만 그건 표일 뿐 파는 물건이 아니고,
나중에 무료 챕터가 같은 표를 쓰면 뺐던 게 사고가 된다.

```
node tools/demo-build.mjs               # web/ → site/play/
node --test tests/node/demo.test.mjs    # 구운 결과에 유료 id 가 남았는지
```

`demo.test` 는 **구운 파일을 열어서** 본다 — 소스가 그럴 작정인지가 아니라 결과물에 실제로 없는지.
유료 콘텐츠를 무료 파일에 섞으면 여기서 빨개진다. 그게 이 검사의 목적이다.
산출물은 커밋하지 않는다(`.gitignore`) — `pages.yml` 이 배포 직전에 굽는다(`vercel.json` 도 같은 명령을 쓴다).

### 캐시 이름에 내용 지문이 붙는다

```
const CACHE_VERSION = 'catpaw-v1.0.0-demo-50a2d865'
                                          ^^^^^^^^ 구운 파일들의 지문
```

서비스 워커가 **캐시 우선**이라(`sw.js` 의 `caches.match`) 캐시 이름이 그대로면 **이미 방문한 사람은
새 빌드를 영영 못 받는다.** 앱 버전만 붙였더니 버전 올리는 걸 잊는 순간 조용히 그렇게 됐다 —
실제로 1.0.0 이후 배포 넷이 사람에게 안 닿고 있었다(배포는 넷 다 초록이었다).

`contentFingerprint` 가 구운 `.js/.html/.css/.webmanifest/.json/.svg` 의 **경로와 내용**으로 8자리를 만든다.
그림·소리는 안 읽는다(이름이 같으면 내용도 같다고 본다 — PNG 100장을 매번 읽을 이유가 없다).
내용이 같으면 지문도 같아 **헛되이 캐시를 버리지도 않는다**. `demo.test` 가 둘 다 검사한다.

전체판(APK·`web/`)은 이 지문을 안 쓴다. APK 는 서비스 워커를 아예 안 쓰고 `web/` 은 호스팅하지 않는다 —
거기서는 `tools/bump-version.mjs` 로 버전을 올리는 규율이 그대로다(`version.test` 가 다섯 곳을 대조).

### 가로 화면 안내 막

지도가 9×14 라 타일 크기는 사실상 높이가 정한다: **타일 ≈ (높이 − 190) / 14**. 아이폰 가로는 14.5px 인데
손가락은 44px 다. 그래서 `web/css/style.css` 끝의 미디어 쿼리가 **가로 + 높이 560px 미만**에서 막을 띄운다
(560 = 26px 타일). 태블릿 가로(820)·데스크톱(800)은 안 걸린다.

상태는 CSS 에만 있다 — 회전하면 저절로 꺼진다. `main.js` 가 하는 일은 '이대로 하기' 가 누르면
`html.rotate-ok` 를 붙이는 것 하나뿐이다(창이 작은 데스크톱용 탈출구).
기준값을 고치면 스모크의 가로 패스가 같이 확인한다.

## 19. 속성과 상성 (`domain/elements.js`)

여섯 원소가 **하나의 고리**를 이룬다. 각 속성은 고리의 **다음** 속성에게 강하다.

```
흙 → 번개 → 얼음 → 불 → 어둠 → 빛 → 흙
```

유리 **×1.5** · 무관 **×1.0** · 불리 **×0.7**. 값은 이 셋뿐이다.

**왜 고리인가 — 빛↔어둠을 서로 강하게 두지 않은 이유.** 처음엔 4원소 고리 + 빛↔어둠 상호 우위로 짰다.
그러면 빛과 어둠만 **약점이 하나도 없다**(서로에게 1.5, 나머지 넷에겐 1.0). 고양이는 공격만 하므로
약점 없는 속성은 언제나 정답이 되고 상성이 그 자리에서 죽는다. 고리면 여섯 전부 **강점 1 · 약점 1 · 무관 3** 이다 —
`elements.test` 가 이 대칭을 직접 센다. 물리가 아니라 설계다.

### 어디에 걸리나

| 자리 | 무엇 |
|---|---|
| `game.js` `applyDamage` | **방어력을 뺀 뒤에** 곱한다. 앞에 곱하면 장갑이 뺄셈이라 "×1.5" 가 적마다 다른 값이 돼 화면에서 안 읽힌다 |
| `game.js` `_effectCtx(tower, …)` | 타워의 속성을 ctx 에 한 번 얹는다 — **효과 7종·직격·투사체가 전부 이 길을 지나므로** 효과 하나하나가 속성을 알 필요가 없다 |
| `game.js` dot 틱 | 속성이 다른 스택은 따로 때린다(합쳐 때리면 상성이 섞인다). 상성이 꺼진 판은 **예전 경로 그대로** |
| 필살기 | **무속성이다.** 전역기에 상성을 얹으면 원정이 필살기 싸움이 된다 |

### 언제 켜지나 — 기본은 꺼짐

`rules.elemental` 이 켜진 판에서만 걸린다. **자유 모드와 시나리오는 그대로다** — 맵을 깨고 나가는 길이
속성 수집에 걸리면 안 된다(README 무료 범위 약속). `RULE_KEYS` 에 있으므로 도전으로도 켤 수 있고,
`new Game({ rules: { elemental: true } })` 로도 켤 수 있다(원정 모드가 쓰는 길).

`game.test` 에 **"꺼져 있으면 배수가 안 걸린다"** 검사가 있다. 이게 J 단계 전체의 안전장치다 —
여기가 빨개지면 E 단계에서 잡은 세 난이도가 통째로 흔들린 것이다.

### 속성을 더하거나 바꾸려면

```js
// domain/elements.js — 고리 순서 그대로. 각 원소는 다음 원소에게 강하다.
export const ELEMENTS = ['earth', 'bolt', 'ice', 'fire', 'dark', 'light']
```

배열에 하나를 끼워 넣으면 고리가 그만큼 길어진다. 이름(`ELEMENT_NAMES`)과 배지(`ELEMENT_LOOK`)를 같이 채워야
하고, `elements.test` 가 **셋 다 개수가 맞는지**와 대칭을 본다. 새 이름은 `i18n/en.js` 에도 넣는다
(`i18n-scan` 이 `domain/elements.js` 를 본다).

콘텐츠 쪽은 한 줄이다:

```js
registerTower({ id: 'cheese', element: 'light', … })
registerEnemy({ id: 'mouse',  element: 'earth', … })
```

**속성은 없어도 된다**(생략하면 무속성 = 늘 1.0). 다만 **오타는 등록이 거부한다** — `'fier'` 라고 적으면
조용히 무속성이 돼 상성이 영영 안 걸리기 때문이다. 그리고 `elements.test` 가
**여섯 속성이 고양이·적 양쪽에서 최소 한 번씩 쓰이는지** 본다(어느 쪽에도 없는 속성은 쓸 데가 없다).

## 20. 뽑기 — 확률을 고칠 때 (`domain/gacha.js`)

**표는 하나뿐이다.** `GACHA_TABLE` 이 굴리는 표이자 화면에 뜨는 표다.

```js
export const GACHA_TABLE = [
  { id: 'legend', name: '전설', weight: 0.02, desc: '…', pool: { kind: 'cat', rarity: 'legend' }, pity: true },
  …
]
```

`weight` 는 **확률 그대로**다(합이 정확히 1). 가중치를 따로 두면 화면에 띄울 때 다시 계산해야 하고,
그 계산이 표와 어긋나는 순간 **공개한 확률이 거짓말이 된다.**

### 왜 이렇게까지 하나

캣닢은 현금으로도 산다(`shop.js` 의 `catnip_100`·`catnip_600`). 그래서 이 뽑기는 **확률형 아이템**이고,
한국 게임산업법이 확률 공개를 의무화한다(2024-03 시행). 그 법이 요구하는 것은 "표를 띄워라"가 아니라
**"띄운 값이 실제 값이어야 한다"** 다. `gacha.test` 가 그걸 세 겹으로 본다:

| 검사 | 무엇을 막나 |
|---|---|
| 합이 1.0 | 표 자체가 말이 안 되는 것 |
| `disclosureRows()` 가 표에서 나온다 | 화면 문구와 실제 표가 어긋나는 것 |
| **20만 번 굴린 실측이 표와 맞는다** | 굴리는 코드가 표대로 안 굴리는 것 |

셋째가 진짜 증거다. 앞의 둘은 코드가 스스로 일관됐다는 것뿐이다.

### 확률을 바꾸려면

`weight` 를 고치고 `npm test` 를 돌린다. 합이 1이 아니면 즉시 빨개진다.
화면 문구는 **안 고친다** — `disclosureRows()` 가 표에서 만든다.

### 약속 셋

- **뽑기가 진행을 막지 않는다.** 기존 고양이 9마리는 시나리오 보상으로 전부 무료다. 뽑기에서 나오는 것은
  그 위에 얹는 것(새 고양이 · 속성 룬)뿐이다.
- **빈손으로 돌려보내지 않는다.** 중복 카드는 조각으로 녹고(`SHARDS_PER_DUPLICATE`), 새 고양이가
  하나도 없는 빌드(데모)에서도 조각으로 바꿔 준다. 판돈을 받고 아무것도 안 주는 일이 없다.
- **운이 나빠도 결국 도달한다.** 조각 `SHARDS_PER_CARD` 개로 **원하는** 카드를 산다. 10연에는
  상위 등급 하나가 보장된다(`PITY_AT`) — 이 보장도 표와 함께 공개한다.

### 티켓 — 현금으로 못 사는 자원

`shop.js` 에 티켓 상품이 **없다.** 출석(`DAILY_TICKETS`, 하루 1장)과 원정 보상으로만 벌린다.
뽑기를 돌리는 무료 길이 여기라서, "결제 없이도 모을 수 있다"는 약속이 뽑기까지 이어진다.
`cards.js` 의 `canDraw` 가 **티켓을 먼저 쓴다** — 현금으로 못 사는 자원을 남겨 둘 이유가 없다.

### 뽑기 풀은 `rarity` 한 줄로 정한다

```js
registerTower({ id: 'ember', rarity: 'epic', … })   // 뽑기에서 나온다
registerTower({ id: 'cheese', … })                  // 등급이 없다 = 안 나온다
```

`cardPools()`(`content/registry.js`)가 등급이 붙은 고양이만 모아 `gacha.js` 가 받는 모양으로 준다.
**등급이 없으면 안 나온다** — 시나리오 보상으로 무료로 주는 고양이가 뽑기 풀에 섞이면
"이미 가진 것이 또 나온다"가 되고, 무엇보다 무료로 주기로 한 것을 파는 셈이 된다.
오타(`'lengend'`)는 `registerTower` 가 던진다. 지금은 등급이 붙은 고양이가 하나도 없어 두 풀이 다 비어 있고,
그때는 `gacha.js` 가 조각으로 바꿔 준다(빈손 없음).

카드를 가지면 그 고양이를 쓸 수 있다 — `game.isTowerUnlocked` 가 `unlockedTowers` **와** `cards.owned` 둘 다 본다.
카드를 `unlockedTowers` 에 같이 밀어 넣지 않는 이유: 콘텐츠에서 그 고양이를 빼는 날 해금 목록에 유령 id 가 남는다.

### 화면 — 확률 표는 손으로 안 적는다

| 자리 | 무엇 |
|---|---|
| `ui.openGacha` | 표 전체를 `disclosureRows()` 로 그린다. **문구를 여기 적으면 안 된다** — `gacha.js` 를 고칠 때 한쪽만 고쳐진다 |
| `ui.openRunes(towerId)` | 고양이 하나의 룬 시트. 6속성 + 기본. 약점 문구는 `beats`/`beatenBy` 가 만든다 |
| 도감 `카드` 탭 | 가진 카드·조각·룬 개수. 조각 교환 버튼 |
| `main.onDraw` | 난수는 **시드를 안 박는다**(`Math.random`). 주간 도전과 반대다 — 시드가 있으면 저장을 백업했다 덮어써서 결과를 고를 수 있다 |

스모크(`tools/screenshot.mjs`)가 **화면에 뜬 퍼센트 문자열이 `disclosureRows()` 의 값과 같은지**를 잰다.
`gacha.test` 가 못 잡는 마지막 한 칸이 "화면에 실제로 그 값이 떴는가"다.

### 보관 규칙은 `domain/cards.js` 에

`gacha.js` 는 **무엇이 나오는지**만(순수·시드), `cards.js` 는 **그것을 어떻게 갖는지**만 안다.
나눈 이유: 확률은 공개하는 약속이라 그 파일이 표 하나로 얇아야 한다.

**룬은 소모되지 않는다.** 가진 개수는 "몇 마리에게 **동시에** 끼울 수 있나"를 뜻한다.
소모품으로 두면 원정마다 다시 뽑아야 해서 상성 맞추기가 자원 스트레스가 된다 —
대신 그 개수 제한이 원정의 밸런스 제동 중 하나다.
