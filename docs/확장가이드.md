# 확장 가이드

이 게임의 콘텐츠는 전부 **데이터**다. 아래 작업 중 어떤 것도 `game.js` / `render.js` / `ui.js`를 고치지 않는다.

무엇을 추가하든 마지막에 이것만 돌리면 된다:

```bash
npm test
```

`content.test.mjs`가 참조 무결성·밸런스 곡선을 다시 검사하고, 게임을 열면 `validateAll()`이 부팅 때 한 번 더 검사한다.
오타가 나면 조용히 깨지지 않고 **한국어 에러 메시지**가 타이틀 화면에 그대로 뜬다.

## 1. 새 고양이(타워) 추가

`web/js/content/towers.js` 맨 아래에 블록 하나를 붙인다.

```js
registerTower({
  id: 'ninja',                 // 다른 타워와 겹치면 ContentError
  name: '닌자냥',
  order: 6,                    // 상점·도감 정렬 순서
  desc: '그림자에서 표창을 던진다. 사거리는 짧지만 연사가 매우 빠르다.',
  sprite: 'cat',               // sprites.js에 등록된 키
  targets: 'all',              // 'all' | 'ground' | 'air'
  palette: { fur: '#3d4a5c', belly: '#93a3b8', stripe: '#2a3441', eye: '#ff6b6b' },
  levels: [
    // levels[0].cost = 건설비 / 나머지 cost = 그 레벨로 올리는 업그레이드비
    { cost: 150, damage: 9,  range: 2.0, fireRate: 3.2, projectile: 'dart', effects: [] },
    { cost: 110, damage: 15, range: 2.2, fireRate: 3.8, projectile: 'dart', effects: [] },
    { cost: 220, damage: 24, range: 2.4, fireRate: 4.4, projectile: 'dart', effects: [] },
  ],
})
```

끝이다. 상점 카드, 도감 항목, 업그레이드 패널, 사거리 표시가 전부 자동으로 생긴다.

| 필드 | 단위 / 규칙 |
|---|---|
| `range` | 타일 |
| `fireRate` | 발/초 |
| `damage` | 1발당. 적 방어력만큼 깎이고 **최소 1은 들어간다** |
| `projectile` | `'pellet'`·`'bomb'`·`'gaze'`·`'dart'` 또는 `null`(즉시 타격) |

> 테스트가 **레벨이 오를수록 DPS가 증가**하는지 검사한다. `damage × fireRate`가 단조 증가해야 한다.

## 3. 새 스프라이트(그림) 추가

`web/js/sprites.js`에 그리는 함수를 만들고 등록한다.

```js
function drawWasp(ctx, o) {
  const { x, y, r, palette: p, angle = 0, t = 0 } = o
  ctx.save()
  ctx.translate(x, y)
  // ... 캔버스 프리미티브로 그린다 (이미지 파일은 쓰지 않는다)
  ctx.restore()
}
registerSprite('wasp', drawWasp)
```

계약: `x, y`는 화면 픽셀 중심, `r`은 픽셀 반지름, `angle`은 바라보는 방향(라디안), `t`는 경과 시간(초, 애니메이션용).
함수는 **스스로 `save`/`restore`** 해야 하며 호출자의 변환 상태를 바꾸면 안 된다.

## 3-b. 프레임 아트(그림 파일)로 캐릭터 갈아끼우기

캔버스로 그린 벡터 대신 채색 그림을 쓴다. **그림이 없으면 자동으로 벡터로 떨어지므로
한 캐릭터씩 넣어도 된다.**

### 그림 규격

가로로 프레임을 붙인 스트립 한 장. 프레임 수는 종류마다 다르다.

**고양이 — 5장** (`169×169` × 5 = `845×169`)

| 프레임 | 뜻 | 언제 |
|---|---|---|
| 0 | 발사 순간 | `recoil >= 0.82` |
| 1 | 되돌아오는 중 | `>= 0.48` |
| 2 | 거의 제자리 | `>= 0.15` |
| 3 | 대기 | 그 아래 |
| 4 | 자는 중 | 5초 넘게 안 쏘면 |

**해충 — 3장** (`209×209` × 3 = `627×209`)

| 프레임 | 뜻 | 언제 |
|---|---|---|
| 0 | 걷기 A | 초당 6회 B와 번갈아 |
| 1 | 걷기 B | 〃 |
| 2 | 멈춤 | 속도 배율 0.5 이하 (자장가 등) |

해충에 피격·죽음 프레임은 요청하지 않는다. 피격 번쩍임은 `ctx.filter` 로,
보호막·광폭화 고리·엘리트 왕관은 코드가 그린다. 안 쓸 프레임을 빼면 같은 가로
폭에서 칸이 커진다 = 그림이 커진다.

- **PNG-32, 배경 완전 투명**
- **오른쪽을 보게** 그린다. 타깃이 왼쪽이면 코드가 통째로 좌우 반전한다
- **방향성 효과(칼·룬 원·속도선·잔상)는 그림에 넣는다.** 반전으로 방향이 맞춰지고,
  코드가 회전 효과를 덧그리면 이중으로 보인다
- **바닥 그림자도 그림에 넣는다.** 그림을 쓰면 코드가 그림자를 그리지 않는다

### 등록

`web/js/framesets.js`:

```js
registerFrameSet('cat-newcat', {
  src: 'art/cat-newcat.png',
  frames: 5, w: 169, h: 169,
  body: { cx: 82, cy: 73, h: 107 },   // ★ 대기 프레임에서 고양이가 차지하는 영역
})
```

`body` 를 왜 주는가: 그림 안에서 캐릭터가 프레임을 꽉 채우지 않는다. 이 값이 없으면
벡터에서 그림으로 바꿀 때 크기와 바닥 위치가 어긋난다. 실측값은
`tools/slice-sheet.mjs` 가 표로 출력한다. 고양이 5마리는 모두 같은 값이라
`CAT` 상수를 공유한다.

선택 항목 세 개:

| 항목 | 뜻 | 언제 쓰나 |
|---|---|---|
| `hPerR` | 이 캐릭터가 화면에서 쓰는 세로 폭 (반지름 r 배수) | 생쥐 1.85 · 흡혈 박쥐왕 1.49 처럼 캐릭터마다 다르다. 안 주면 고양이 기준(2.18)이라 해충이 전부 고양이 크기로 나온다 |
| `cyPerR` | 같은 기준의 세로 중심 | 〃 |
| `shadow` | `{ cy, rx, ry, alpha }` — 코드가 그릴 바닥 그림자 | **그림에 그림자가 없을 때만.** 보스 시트가 그 경우다 |

`hPerR`/`cyPerR` 은 눈대중이 아니라 실측한다. 스프라이트를 오프스크린 캔버스에 그리고
알파 경계를 재면 된다. 바닥 그림자는 `globalAlpha 0.26` 으로 그려지므로 **알파 200
이상만 세면 몸만** 잴 수 있다.

그리고 타워 정의(`content/towers.js`)에 한 줄:

```js
registerTower({ id: 'newcat', sprite: 'cat', pose: 'jab', frames: 'cat-newcat', ... })
```

- `frames` 를 빼면 지금까지처럼 벡터로 그려진다
- 그림에 없는 효과를 코드로 덧그려야 하면 `effectOverArt: true` 를 준다
  (샴냥이 유일한 예 — 그림에 눈빛이 없어서 `gaze` 포즈의 효과만 얹는다)
- 오타는 부팅 때 `validateAll()` 이 잡고 등록 방법과 쓸 수 있는 목록을 알려준다
- **`web/sw.js` 의 `ASSETS` 에 `art/...png` 를 넣고 `CACHE_VERSION` 을 올린다**
  (§11 참조 — `tests/node/sw.test.mjs` 가 빠뜨림을 잡는다)

### 알파 없는 시트에서 잘라 쓸 때

`tools/slice-sheet.mjs` 가 `art-src/pose-sheet-cats.png`(5×5 격자, 배경 불투명)에서
`web/art/cat-*.png` 를 굽는다. 배경을 파내는 방식이 단순 임계값이 **아니다**:

1. 셀별 지역 배경을 링 중앙값으로 추정 (배경이 60~68로 평탄하지 않다)
2. 배경과의 차이로 알파 램프
3. **가장자리에서 flood fill 해 배경과 이어진 곳만 지운다** — 뚱냥의 회색 먼지·잔상이
   배경색과 가까워서, 값으로만 판단하면 통째로 사라진다
4. 배경값과 같은 픽셀 중 **200px 이상 뭉친 덩어리**는 둘러싸여 있어도 배경으로 인정
   — 삼색냥 룬 원 안쪽이 불투명한 검은 원반으로 남는 것을 막는다. 크기 조건이 없으면
   검은냥의 회색 털 하이라이트까지 뚫려 몸에 구멍이 난다
5. 언프리멀티플라이로 회색 띠 제거

시트가 늘어나서 격자·키잉 설정은 파일 맨 위 `SHEETS` 표로 뺐다. 시트마다 다른 값:

| 항목 | 뜻 |
|---|---|
| `cols`/`rows`/`size`/`ring` | 격자 좌표와 셀 크기, 테두리선을 지울 폭 |
| `lo`/`hi`/`fillT` | 알파 램프 시작·끝, flood fill 이 통과할 수 있는 차이 |
| `aaRadius` | 실루엣에서 이만큼 넘게 떨어진 배경은 무조건 투명 |
| `dropSmallParts` | 캐릭터와 이어지지 않은 작은 덩어리를 지운다 (셀에 찍힌 프레임 번호 등) |
| `masks` | 시트 좌표로 지정해 지울 영역 (발주서 안내 문구 등) |
| `shadow` | 그림자가 지워지는 시트라는 표시 — 프레임셋에 `shadow` 를 함께 준다 |

**보스 시트가 왜 다른 설정을 쓰나**: 그 시트만 캐릭터 뒤에 푸른 후광이 깔려 나왔다.
기본 설정으로는 후광이 검은 원반처럼 통째로 남는다. 실측하니 후광은 배경차이 12~48 ·
저채도이고 캐릭터 몸은 60 이상이라, **fill 이 후광을 통과하도록 `fillT` 를 45 로 올리고
알파 램프는 `hi` 22 로 좁게 둔 뒤, 실루엣에서 2px 넘게 떨어진 곳은 아예 투명**으로
만들었다. 그 과정에서 구워진 바닥 그림자도 지워지므로 프레임셋에 `shadow` 를 준다.

**작은 덩어리 필터가 위치 기반 마스킹보다 나은 이유**: 셀마다 프레임 번호가 찍혀
나왔는데, 위쪽 N% 를 잘라내면 마왕 쥐의 뿔이 같은 높이라 같이 날아간다. 글자는
캐릭터와 이어지지 않은 작은 덩어리이므로 '가장 큰 덩어리의 4% 미만'으로 거른다.
단, 글자끼리 붙어 하나의 긴 덩어리가 되면 이 필터를 통과한다 — 일반 해충 시트의
안내 문구가 그랬고, 그건 `masks` 로 좌표를 찍어 지웠다.

투명 배경 원본이 오면 `--keep-alpha` 로 이 과정을 건너뛴다.
결과 확인은 `tools/out/14-slice-check.png`(체커보드 격자)와
`tools/out/12-poses.png`(게임과 같은 `drawUnit` 으로 그린 모션 시트).

## 4. 새 능력(effect) 추가

`web/js/content/effects.js`에 핸들러를 등록하고, 타워 레벨의 `effects`에 넣는다.

```js
registerEffect('burn', {
  onHit(ctx, fx, target) {
    // fx = 타워 데이터에 쓴 객체 그대로: { kind:'burn', dps:8, duration:3 }
    ctx.applyDamage(target, fx.dps)
    ctx.spawnParticle(target.x, target.y, { kind: 'hit', color: '#ff8a3d' })
  },
})
```

```js
// towers.js — 그 다음 이렇게 쓴다
{ cost: 200, damage: 20, range: 2.5, fireRate: 1.0, projectile: 'pellet',
  effects: [{ kind: 'burn', dps: 8, duration: 3 }] },
```

**핸들러 계약**

| 훅 | 호출 시점 | 반환 |
|---|---|---|
| `onFire(ctx, fx, target)` | 발사 순간 | `{ consumed: true }`를 주면 투사체를 만들지 않는다 (뚱냥의 광역기가 이 방식) |
| `onHit(ctx, fx, target)` | 투사체 명중 순간 | 무시됨 |

`ctx`로 쓸 수 있는 도구:

```
ctx.tower                            발사한 타워 (타일 좌표, range, targets)
ctx.now                              게임 내부 시각(초)
ctx.damage                           이번 발사의 기본 공격력
ctx.enemies                          살아 있는 적 배열
ctx.applyDamage(enemy, amount)       방어력 적용 후 피해 (처치·골드 정산 포함)
ctx.enemiesInRadius(x, y, r, opts)   반경 내 적. opts.exclude / opts.targets
ctx.addSlow(enemy, factor, sec)      적 저항을 반영한 슬로우
ctx.spawnParticle(x, y, opts)        연출
ctx.playSfx(name)                    효과음
```

등록하지 않은 `kind`를 타워에 쓰면 부팅 때 이렇게 막힌다:

```
타워 'x' 레벨 1이(가) 등록되지 않은 효과 'burn'을(를) 참조합니다.
content/effects.js에 registerEffect('burn', ...)를 추가하세요.
```

## 5-b. 지도 아트(길 질감 · 막힌 칸 소품)

캐릭터 아트와 같은 규칙이다 — **그림이 없으면 지금의 단색 렌더링으로 조용히 떨어진다.**
한 맵씩 넣어도 되고, 오타는 부팅 때 걸린다.

### 핵심: 기하는 한 글자도 안 바꾼다

`fillStyle` / `strokeStyle` 은 색뿐 아니라 `CanvasPattern` 도 받는다. 그래서 길에
질감을 입힐 때 **폴리라인을 건드리지 않는다** — 색을 넣던 자리에 패턴을 넣을 뿐이다.

```js
const pat = getPathPattern(game.mapDef.id, ctx, t, this.ox, this.oy)
ctx.strokeStyle = pat || game.mapDef.theme.path   // 패턴이 없으면 단색
ctx.lineWidth = t * 0.78
ctx.stroke()
```

이렇게 하면 **길 그림과 실제 경로가 어긋나는 사고가 구조적으로 불가능하다.** 통짜
배경 일러스트에 길을 그려 넣는 방식은 이 보장이 없다(실제로 그렇게 받아 봤더니
맵 하나는 실제 경로와 36%밖에 안 겹쳤다).

격자에 맞추는 건 패턴 변환이 한다:

```js
pattern.setTransform(new DOMMatrix().translate(ox, oy).scale(tile * PATCH_TILES / img.width))
```

`PATCH_TILES` 는 질감 한 장이 몇 칸을 덮는지다(지금 2). 화면 크기가 바뀌면 `tile` 과
`ox/oy` 가 달라지므로 패턴을 다시 만든다 — 성능 때문이 아니라(실측 2.3µs) 캐시 키를
`tile|ox|oy` 로 두는 편이 단순해서다.

### 새 질감·소품 등록

`web/js/mapart.js`:

```js
registerMapArt('basement', { path: 'art/path-basement.png' })
registerProp('barrel', { src: 'art/prop-barrel.png' })
```

- `registerMapArt` 는 `path`(길 질감) 또는 `floor`(바닥 질감) 중 하나 이상이 필요하다
- 소품은 **알파 경계를 자동 실측**한다(`solidBounds`). 그림이 칸을 꽉 안 채워도
  바닥에 발이 닿게 놓이므로, 새 소품을 넣을 때 좌표 상수를 적을 필요가 없다
- 막힌 칸이 여럿이면 `(열 + 행) % props.length` 로 번갈아 놓는다 — 같은 그림이
  나란히 붙는 걸 줄인다
- 로드 완료 콜백이 필요 없다. 캔버스는 매 프레임 다시 그리므로 늦게 와도 다음
  프레임에 반영된다

### 시트에서 굽기

`tools/slice-sheet.mjs` 의 `SHEETS` 표에 시트를 더한다. 캐릭터 시트와 두 가지가 다르다:

| 옵션 | 뜻 |
|---|---|
| `raw: true` | 파낼 배경이 없다 — 자르기만 한다 (길 질감은 셀 전체가 그림이다) |
| `perCell: true` | 한 행이 한 캐릭터의 프레임 묶음이 아니라, **칸 하나가 각각 독립된 그림**이다 |

`perCell` 이 없으면 3열짜리 지도 시트가 "3장이 가로로 이어붙은 스트립" 하나로 나온다.

굽고 나면 반드시 체커보드 확인 이미지를 **눈으로 본다** (`14-slice-check-paths.png`,
`14-slice-check-props.png`). 지금까지 슬라이스 사고는 전부 여기서 잡혔다.

### 그림을 발주할 때 — 시트에 넣으면 안 되는 것

생성 도구는 **전체 출력 크기가 대체로 고정**(640~830px)이다. 칸을 나눌수록 칸당
해상도가 무너진다. 그래서:

- **시트로 받는다**: 질감 · 소품 · 캐릭터 프레임 — 작아도 되는 것
- **한 장씩 따로 받는다**: 화면을 꽉 채우는 그림(타이틀 배경 등)

한 시트에 전체화면 배경 3장을 넣어 달라고 했다가 186×286 으로 받은 적이 있다.
1152×1792 로 쓰려면 6.2배 확대라 못 썼다.

`tools/map-spec.mjs` 가 발주서 이미지를 만든다.

## 10. 저장 데이터 구조를 바꿀 때

`web/js/domain/save.js`에서 `SAVE_VERSION`을 올리고 `migrate()`에 단계를 이어 붙인다.
기존 사용자의 저장 데이터가 깨지지 않게 하는 유일한 방법이다.

```js
export const SAVE_VERSION = 4

// migrate() 안, v2 → v3 블록 다음에
if (version < 4) {
  cur = { ...cur, version: 4, 새필드: 기본값 }
  migrated = true
}
```

**★ 마지막 정규화 단계(`const progress = { ... }`)에도 새 필드를 반드시 넣는다.**
안 넣으면 마이그레이션은 통과하는데 값이 조용히 사라진다. 저장·불러오기를 왕복하는
테스트를 같이 쓰면 이 실수를 바로 잡는다.

읽을 수 없는 데이터(깨진 JSON, 더 최신 버전)는 **지우지 않고** `catpaw.progress.backup` 키로 옮긴 뒤 기본값으로 시작한다.

`web/js/content/enemyAbilities.js`에 핸들러를 등록하고, `enemies.js`의 `abilities`에 넣는다.

```js
registerEnemyAbility('teleport', {
  onTick(ctx, ab, e) {
    if (ctx.now < (e.nextBlink || 0)) return
    e.nextBlink = ctx.now + (ab.every || 8)
    e.progress += ab.distance || 2          // 앞으로 순간이동
```

```js

```

**훅 계약**

| 훅 | 호출 시점 | 반환 |
|---|---|---|
| `onSpawn(ctx, ab, e)` | 등장 순간 | 무시됨 (상태 초기화용) |
| `onTick(ctx, ab, e, dt)` | 매 시뮬레이션 스텝 | 무시됨 |
| `onDamaged(ctx, ab, e, dmg)` | 피해 직전 | **숫자를 반환하면 그 값으로 대체**된다 (보호막이 이 방식) |
| `onDeath(ctx, ab, e)` | 사망 순간 | 무시됨 (분열이 이 방식) |

`ctx`로 쓸 수 있는 도구:

```
ctx.now, ctx.enemies
ctx.spawnMinion(enemyId, { progress, hpMul })   부하 소환
ctx.enemiesInRadius(x, y, r, { exclude })
ctx.spawnParticle(x, y, opts), ctx.addFloater(x, y, text, color)
ctx.playSfx(name), ctx.flash(color, strength), ctx.shake(amount)
```

**스탯 보정 규약**: 능력은 매 스텝 0으로 초기화되는 `e.auraArmor` / `e.auraSpeed` 에만 쓴다.
`e.def`를 직접 고치면 그 정의가 다음 판까지 오염된다 — 절대 하지 않는다.

> 등록하지 않은 kind를 쓰면 부팅 때 `registerEnemyAbility('teleport', ...)를 추가하세요` 라고 알려준다.

```js
  order: 5,

  catnip: 22,              // 캣닢으로 즉시 충전할 때의 값
  run(ctx) {

      ctx.applyDamage(e, dmg)

  },
```

HUD의 버튼·쿨다운 링·마나 비용 표시·부족량 안내가 전부 자동으로 따라온다.

## 13-c. 엘리트(왕관) 변종 조정

적 정의를 새로 만들지 않고 후반 압박만 올리는 장치다. `web/js/domain/elite.js`:

| 상수 | 현재 | 뜻 |
|---|---|---|
| `ELITE_FROM_WAVE` | 6 | 이 웨이브부터 등장 |
| `ELITE_CHANCE_PER_WAVE` | 0.012 | 웨이브당 확률 증가폭 |
| `ELITE_CHANCE_MAX` | 0.22 | 확률 상한 (넘기면 화면이 왕관으로 뒤덮인다) |

규칙 두 가지를 지켜야 한다.

- **보스에게는 붙지 않는다.** 이미 왕관을 쓰고 능력도 따로 있다.
- **정의의 팔레트를 절대 고치지 않는다.** `elitePalette()` 는 새 객체를 만든다.
  원본을 고치면 그 종류 전체가 다음 판까지 왕관을 쓰고 나온다.

왕관 그림은 이미 `sprites.js` 가 `palette.crown` 을 보고 그린다. 새 적을 추가할 때
스프라이트에 왕관 처리를 넣어두면 엘리트도 공짜로 따라온다.

## 14. 새 파티클(연출) 종류 추가

두 곳을 건드린다.

1. `web/js/game.js`의 `Game.RING_KINDS` — 고리처럼 퍼지는 연출이면 여기에 이름을 넣는다
2. `web/js/render.js`의 `_drawParticles` switch에 `case '이름':` 추가

```js
// render.js
case 'lightning':
  ctx.globalCompositeOperation = 'lighter'
  ctx.strokeStyle = p.color
  ctx.lineWidth = t * 0.08
  ctx.beginPath()
  ctx.moveTo(x, y - t)
  ctx.lineTo(x + t * 0.2, y)
  ctx.lineTo(x, y + t)
  ctx.stroke()
  break
```
