# Play Console 제출 팩

**이 문서는 그대로 복사해서 붙이는 용도다.** Play Console 의 각 칸에 무엇을 적을지 미리 다 써 뒀다.
값은 손으로 적은 게 아니라 코드에서 뽑았다 — 상품은 `domain/shop.js`, 확률은 `domain/gacha.js` 다.
둘 중 하나를 고치면 **이 문서도 같이 고쳐야 한다**(검사가 잡아 주지 않는 유일한 자리다).

빈칸은 딱 둘이다: **연락처 이메일**과 **출시일**. 그 둘만 정하면 나머지는 복사·붙여넣기다.
**순서는 [`출시체크리스트.md`](출시체크리스트.md) 의 ①~⑩** 을 따른다 — 특히 개인정보처리방침 URL 을 넣기 전에 도메인(④)을 먼저 붙인다.

## 4. 확률형 아이템 확률 공개 — **필수**

캣닢을 현금으로도 사고 그 캣닢으로 뽑기를 돌리므로 이 게임은 확률형 아이템을 포함한다.
**한국 게임산업법이 확률 공개를 의무화한다(2024-03 시행).** 게임 안에는 이미 표가 떠 있고
(타이틀 → 뽑기), 스토어 설명과 광고물에도 같은 값을 적어야 한다.

### 스토어 설명 맨 아래에 붙일 문구 (그대로 복사)

```
[확률형 아이템 정보]
이 게임에는 확률형 아이템(고양이 카드 뽑기)이 포함되어 있습니다.
뽑기 1회당 등급별 획득 확률은 다음과 같습니다.

· 전설 (새 고양이)   2.00%
· 희귀 (새 고양이)  10.00%
· 속성 룬          38.00%
· 카드 조각        50.00%

· 10회 연속 뽑기에는 전설 또는 희귀가 1개 이상 확정 지급됩니다.
· 중복된 고양이 카드는 카드 조각 40개로 전환됩니다.
· 카드 조각 300개로 원하는 고양이 카드를 직접 교환할 수 있습니다.
· 속성 룬은 6종(흙·번개·얼음·불·어둠·빛)이 균등하게 나옵니다.
· 뽑기에 쓰는 티켓은 현금으로 판매하지 않으며, 출석과 원정 보상으로만 획득합니다.
· 위 확률은 게임 내 뽑기 화면에서도 동일하게 표시됩니다.

[아이템별 확률]
· 전설 고양이(메인쿤냥 · 사바나냥) 각 1.00%
· 희귀 고양이(터키시앙고라냥 · 벵갈냥 · 노르웨이숲냥 · 먼치킨냥) 각 2.50%
· 속성 룬 종류마다 6.33%
· 카드 조각 15개 50.00%
· 10회 연속 뽑기의 마지막 장은, 앞 9장에 새 고양이가 한 장도 없을 때(31.65%)만
  전설 고양이 각 8.33% · 희귀 고양이 각 20.83% 로 바뀝니다.
· 전체 확률 정보는 게임 안 뽑기 화면('낱개 확률')과 공식 사이트의 '확률 정보' 페이지에 있습니다.
```

**이 숫자는 `domain/gacha.js` 의 `GACHA_TABLE` 에서 나온 것이다.** 표를 고치면 여기도 고쳐야 한다 —
`store-listing.test` 가 이 블록의 등급·아이템·보장 칸 숫자를 `disclosureRows`·`itemOdds`·`pityOdds` 와 대조한다(W).
게임 안 표와 사이트의 확률 페이지(`site/odds.html`)는 같은 함수에서 자동으로 나오고, 검사가 20만 번 굴려 실측까지 대조한다.
**광고·홍보물**에는 "확률형 아이템 포함" 을 표시한다(게임산업법).

## 6. 데이터 안전 양식

**먼저 사실 (W 에서 바로잡았다).** 게임 코드(`web/`)는 아무것도 보내지 않는다 — 서버가 없고 네트워크 호출도 없다.
그러나 **앱 전체로는 기기 밖으로 나가는 것이 있다**: Google Play 결제 라이브러리(9.1.0)가 딸고 오는 Google 로그 전송 부품
(`com.google.android.datatransport`)이 라이브러리의 작동 기록을 Google 에 보낸다. 그래서 병합된 앱에는
`INTERNET` · `ACCESS_NETWORK_STATE` 가 있다. 결제 라이브러리 6.0.0 릴리스 노트 원문:

> The Play Billing Library 6 release includes additional logging, which provides insight into API usage (such as success
> and failure) and service connection issues. This information will be used to improve the performance of the Play
> Billing Library and provide better support for errors.

W 이전의 이 절과 사이트·방침·등록문안은 **"인터넷 권한 없음 · 아무것도 수집하지 않음"** 이라고 적었다. U-2 에서 결제
라이브러리를 넣은 뒤로는 사실이 아니었고, 권한 그물(아래)이 처음 돈 날 잡혔다.

| 문항 | 답 (권장) |
|---|---|
| 데이터를 수집하거나 공유합니까? | **예** — 아래 한 항목 |
| 데이터 유형 | **앱 정보 및 성능 → 진단** (Google Play 결제 라이브러리의 작동 기록) |
| · 수집 / 공유 | 수집 **예** · 공유 **아니요** |
| · 일시적으로 처리되나 | 아니요 |
| · 필수 / 선택 | 필수 (사용자가 끌 수 없다) |
| · 목적 | 앱 기능 · 분석 (Google 의 말: 라이브러리 성능 개선과 오류 지원) |
| 전송 중 암호화 | 예 (아래 확인할 것 ③) |
| 삭제 요청 방법 | 없음 — 개발자가 가진 데이터가 없다. 기기 안 진행도는 앱을 지우면 함께 지워진다 |
| 광고 ID 사용 | **아니요** — 권한 그물이 `AD_ID` 를 막는다 |
| 제3자 SDK | Google Play 결제 라이브러리 하나 (그 밖에는 androidx — 데이터를 다루지 않는다) |

구매 토큰과 상품 id 는 **기기 안에만** 둔다 — 개발자 쪽으로 가는 것이 없으니 수집이 아니다.

**왜 '진단'을 신고하는 쪽을 권하나.** 데이터 보안 양식의 '수집'은 앱에서 기기 밖으로 보내는 것이고, 앱 안의 SDK·라이브러리가
보내는 것도 포함된다(developer.android.com "Declare your app's data use": *If a third-party SDK or library in your app
collects or shares user data, you must reflect this collection and sharing in the Data safety form*). 도움말 요약에 따르면
Google Play 결제 시스템처럼 결제 서비스가 사용자에게서 **직접** 받는 결제 정보는 신고하지 않아도 되는데, 이 작동 기록까지 그
예외에 드는지는 확인하지 못했다(이 세션에서는 support.google.com 이 막혀 [도움말 10787469](https://support.google.com/googleplay/android-developer/answer/10787469)
원문을 못 읽었다). **덜 신고하면 정책 위반이고, 더 신고하면 스토어 페이지에 '앱 정보 및 성능' 한 줄이 더 뜬다** — 그래서
신고하는 쪽이 안전하다. 개인정보처리방침 §4 는 어느 쪽을 골라도 맞게 써 두었다.

**제출 전에 원문으로 확인할 셋**:
① 결제 라이브러리의 작동 기록이 결제 서비스 예외에 드는가 — 들면 '수집 없음'으로 내도 된다.
② '공유'로 봐야 하나 — Google 이 이 기록을 자기 라이브러리 개선에 쓰므로 서비스 제공자 예외에 드는지가 갈린다.
③ 전송 중 암호화 — datatransport 는 Google 엔드포인트로 HTTPS 로 보내는 것으로 알고 있지만, 이 세션에서 직접 확인하지는 못했다.

**권한은 CI 가 지킨다(W).** `tools/check-permissions.mjs` 가 병합된 릴리스 매니페스트의 권한을 허용 목록과 대조하고,
AGP 병합 보고서로 **출처까지** 본다. `INTERNET` · `ACCESS_NETWORK_STATE` 는 Play 결제 라이브러리 쪽에서 올 때만 통과한다 —
분석 SDK 같은 다른 라이브러리나 우리 매니페스트가 INTERNET 을 들이거나, 광고 ID 가 끼어들면 빌드가 빨개진다. 그때는
이 표를 먼저 고친다. CI 로그에 권한마다 누가 넣었는지가 찍힌다.

**끄는 길도 있다 (권하지 않는다).** 매니페스트에 `tools:node="remove"` 로 두 권한을 빼면 이 기록은 못 나간다. 결제 자체는
Play 스토어 앱이 네트워크를 맡으므로 돌 가능성이 높지만, 실기기에서 검증한 적이 없고 Google 이 안내하는 방식도 아니다.
구매가 조용히 깨질 위험을 지고 할 일은 아니다.

## 7. 개인정보처리방침

Play 는 URL 을 요구한다. 기계는 준비돼 있고 **빈칸 둘만 채우면 된다**:

```bash
# 1) docs/개인정보처리방침.md 의 [연락처] 와 [출시일] 을 채운다
# 2) 변환 — 자리표시자가 남아 있으면 도구가 거부한다(exit 1)
node tools/site-build.mjs --privacy
# 3) 푸시하면 pages.yml 이 올린다
```

주소: 도메인을 붙이면 `https://<도메인>/privacy.html`. 붙이기 전 주소는 `…github.io/-catpaw-defense/privacy.html` 인데,
**Play 스토어 페이지에 공개로 뜨므로 계정 이름이 샌다** — 그래서 도메인이 먼저다([`출시체크리스트.md`](출시체크리스트.md) ④).

## 8. 업로드 키 만들기 (당신만 해야 한다)

**내가 만들면 안 된다.** 서명 키는 앱의 신원이고, 잃어버리면 그 앱을 영영 업데이트할 수 없다.
채팅에 찍힌 키는 유출된 키다. 아래를 당신 컴퓨터에서 직접 돌린다.

```bash
keytool -genkeypair -v \
  -keystore catpaw-upload.jks \
  -alias catpaw \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -storetype PKCS12
# 비밀번호를 두 번 묻는다. 잊지 말고 어딘가에 안전하게 적어 둔다.

# GitHub 시크릿에 넣을 base64
base64 -w0 catpaw-upload.jks > catpaw-upload.jks.b64   # macOS 는 `base64 -i` 로
```

GitHub → 저장소 → Settings → Secrets and variables → Actions → New repository secret 로 **넷**:

| 시크릿 이름 | 값 |
|---|---|
| `CATPAW_KEYSTORE_B64` | `catpaw-upload.jks.b64` 파일 내용 전체 |
| `CATPAW_KEYSTORE_PW` | 키스토어 비밀번호 |
| `CATPAW_KEY_ALIAS` | `catpaw` |
| `CATPAW_KEY_PW` | 키 비밀번호 |

넣고 나서 CI 를 한 번 돌리면 AAB 가 **진짜 키로** 서명된다. 넣기 전에는 디버그 키로 서명되고,
Play 는 그걸 거부한다(`build.gradle.kts` 의 폴백이 그렇게 돼 있다 — 빌드는 되지만 올릴 수는 없다).

`catpaw-upload.jks` 는 **저장소에 커밋하지 않는다.** `.gitignore` 에 이미 `*.jks` 가 있다.

## 9. 저장소 Private 전환 — 지금은 하지 마라

원래 계획은 Private 이었다. 그런데 지금 바꾸면 **사이트와 아이폰 데모가 죽는다**:

- GitHub Pages 는 private 저장소에서 **GitHub Pro 이상**을 요구한다 → `…github.io/-catpaw-defense/` 와
  `/play/` 가 404 가 된다. 지금 아이폰으로 이 게임을 할 수 있는 유일한 길이 그것이다
- 릴리스 자산(APK)도 로그인해야 받아진다 → 사이트의 다운로드 버튼이 남에게 안 열린다

**Play 출시 자체에는 저장소 공개 여부가 아무 상관이 없다.** 그러니 순서는:

1. 지금은 public 으로 두고 Play 출시를 끝낸다
2. 출시 뒤 사이트가 더 필요 없어지면 그때 Private 으로 바꾼다
3. 사이트를 유지하면서 Private 으로 가고 싶으면 Vercel 로 옮긴다 — `vercel.json` 이 이미 준비돼 있다
   (같은 빌드 명령·같은 검사). **단, APK 도 같이 옮겨야 한다.** R 에서 사이트가 APK 를 직접 주게 바꿨는데
   그 받기 스텝은 `pages.yml` 에만 있었다 — 그대로 Vercel 로 갔으면 다운로드 버튼이 404 였다(찾아서 고쳤다).
   지금은 `vercel.json` 의 빌드 명령이 `tools/fetch-apk.mjs` 로 같은 APK 를 받는다. Private 저장소의 릴리스
   자산은 토큰이 있어야 받아지므로 **Vercel 환경 변수에 `GH_TOKEN`(repo 읽기 권한)** 을 넣어야 한다.
   없으면 빌드가 크게 실패한다 — 죽은 버튼을 올리느니 안 올리는 게 낫다. 이 경로는 여기서 실제로
   못 돌려 봤다(이 세션에서 Vercel 이 안 열린다). **첫 Vercel 배포 뒤 다운로드 버튼을 직접 눌러 확인한다.**
